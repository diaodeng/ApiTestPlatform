# 2026-09-04 工单同步配置页面按入库执行顺序重组

## 变更背景

工单同步配置页面（`/ticket/sync-automation`）此前按"配置存储结构"分组（公共配置/同步/映射规则/系统字段/自定义统计/操作/日志拉取配置），同一个执行链路上的配置散落在多个页签，场景开关在 5 张卡片中重复出现 4 种命名风格，连接凭据在 6 处平铺，用户难以回答"某场景的工单会触发哪些动作"。

## 变更内容（仅前端展示重组，零后端改动）

涉及文件：`web/src/views/ticket/syncAutomation/index.vue`（唯一改动文件）。

### 1. 页签重新归组（7 个）

| 旧页签 | 新页签 |
|--------|--------|
| 公共配置 + 同步 + 映射/规则 | 入库流程（按执行顺序 ⓪~⑧ 编号） |
| 同步中的拉取类卡片 + 公共配置中的凭证 | 来源与拉取 |
| 日志拉取配置 | 日志拉取配置（不变） |
| 同步中的评论同步卡片 | 评论同步 |
| 公共配置中的两个通知任务卡片 | 通知任务 |
| 系统字段 + 自定义统计 | 统计与分类 |
| 操作 | 操作（吸收"指定工单手动自动化"独立卡片） |

### 2. 场景 × 步骤 开关总表（新增）

"入库流程"页签顶部新增一张总表，聚合 4 场景 × 7 步骤共 31 个场景开关，行首带总开关（翻译 `translateConfig.enabled`、AI 分类 `aiClassification.enabled`、群推送 `groupPush.enabled`，与后端 `should_run_ai_classification_for_scene` / `is_translation_enabled` / `_should_send_group_push_for_scene` 的总开关语义一致；AI 提取与 automationConfig 三组无总开关，与后端 `_resolve_automation_enabled_for_scene` 一致）。

原 5 张卡片中的 31 个静态开关列已移除（AI 提取 4 个、翻译总开关+4 场景、AI 分类总开关+4 场景、自动化识别/拉日志/AI 分析 12 个、群推送总开关+4 场景），所有开关仅在总表出现一次。卡片头部与表单顶部均有指向总表的说明文字。v-model 绑定路径不变（矩阵通过 `form[section][field]` 动态绑定，字段路径与原静态绑定一一对应，已逐一核对）。

### 3. 入库流程卡片按执行顺序编号

⓪ 自动化关注范围（总闸门）→ 场景×步骤总表 → ① 字段识别与映射（原"映射/规则"页签的识别规则+映射配置合并卡片）→ ② 外部工单字段模型 → ③ AI 提取 → ④ 标题总结 → ⑤ 翻译 → ⑥ AI 分类 → ⑦ 同步后自动化（保留自动化结果通知）→ ⑧ 群推送 → 旁路·知识提炼 → 提示词模板。

### 4. 连接覆盖折叠与解析预览（P3）

- 飞书统一凭证卡移入"来源与拉取"，其中误放的远端同步 `credentialBindingId/origin` 两个字段迁回"远端同步链接"卡片。
- 主动拉取（appToken/tableId/viewId/filterFormula）、邮箱补全（5 字段）、汇总统计（11 字段）、按人催办（7 字段）的连接/凭证字段收入各自卡片的"连接与凭证覆盖（可选）" `el-collapse`，折叠标题提示继承顺序，留空继承、填写覆盖，隐藏不清空。
- "来源与拉取"新增只读"连接解析预览"卡片：按 模块自身 → `bitableCommon` → `feishuAuth` 顺序实时解析 4 个使用方（邮箱补全/主动拉取/汇总统计/按人催办）实际生效的 `appId/appToken/tableId` 并标注来源标签，与后端 `resolve_bitable_runtime_config` 的合并顺序一致（前端仅展示模拟）。

## 明确不做

- 不改后端配置键、不改 `ticket.sync.automation` 存储结构、不改任何接口契约（P5 长期方案另行评估）。
- 不移动 `logPullDefaults`、存储与资源限制、日志拉取外部接口配置（"日志拉取配置"页签原样保留）。
- AI 分类的状态变更触发组（`runOnStatusChange` 等）不属于入库场景，保留在⑥卡片内。
