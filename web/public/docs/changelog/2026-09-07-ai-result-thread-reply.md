# 2026-09-07 - AI 分析结果回帖工单群话题（aiResultFollowUp）

## 功能说明

AI 分析完成后，自动把分析结果**回帖到该工单在工单群的话题中**（不是新建一条独立消息），与工单信息推送使用同一飞书应用、同一优先级路由群。此前 AI 结果只在系统内展示，群里无法按话题跟进工单处理进展。

## 配置入口

同步自动化配置页 →「入库流程」页签 →「⑧ 工单群消息推送」卡片 →「AI 分析结果话题回帖」区块。

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 启用回帖 | 关 | 总开关；仅发送模式为 feishu_app / hybrid 时生效 |
| 推送时机 | 不推送 | 不推送 / 仅分析成功 / 仅分析失败 / 成功和失败都推送；分析取消永不回帖 |
| 话题内回复 | 开 | 回复挂在工单信息话题下；关闭则普通引用回复 |
| 无锚点处理 | 跳过并记录日志 | 工单此前未发过群消息（无话题锚点）时：跳过（默认，防止对历史工单重复发送）；或先补发一条工单信息建立话题再回帖（补发走完整推送判定，已发送过的工单不会重复发送） |
| 回帖模板 | 内置默认 | 留空用默认模板；支持工单变量 + AI 结果变量 |

所有配置默认关闭，功能上线不改变任何现有行为。

## 行为规则

- 回帖目标复用工单信息群推送时记录的话题锚点，按群去重：工单信息发到几个群，AI 结果就回帖几个群。
- AI 终态时工单还没发过群消息（例如首次 AI 直接完成且此前推送条件不满足），会先按正常自动群推送流程补发工单信息消息，成功后再回帖。
- 工单无话题锚点时按「无锚点处理」策略执行：默认跳过并记录日志（历史已在群里跟进过的工单不会重复收到工单信息）；选择"先补发再回帖"时补发走完整推送判定（自动化范围、场景开关、推送条件、仅一次去重），已发送过群消息的工单依然不会重复发送。
- 同一次分析任务只回帖一次（按任务 ID 幂等）；多次重新分析会多次回帖。
- 回帖失败不影响工单发布状态和 AI 任务结果，仅记录失败日志。
- 手动提交 AI 分析时，提交表单新增「结果回帖工单群」下拉：跟随全局配置（默认）/ 本次回帖 / 本次不回帖。

## 与通知机器人的分工

- 通知机器人（自动化结果通知）：通知**自动化执行状态**（日志拉取/AI 分析跑没跑完），面向平台运维视角，配置在「自动化结果通知」卡片。
- 工单群话题回帖：通知**工单处理内容**（AI 分析出的结论、根因、建议），面向工单处理人，配置在群推送卡片。

两者独立配置、互不影响。

## 服务端变更

- `groupPush.aiResultFollowUp` 配置结构与归一化（`ticket_sync_config_service.py`），含 `noAnchorStrategy` 无锚点策略（skip 默认 / send_then_reply）。
- `TicketSyncGroupPushService.send_ai_result_thread_reply`：配置判定、task_id 幂等、锚点去重、逐群回帖、失败不中断；无锚点按策略分叉。
- `TicketSyncGroupPushService.send_group_message_for_ai_reply`：补发工单信息消息（复用自动群推送全套判定：范围/场景开关/推送条件/仅一次去重/并发锁），供 send_then_reply 策略建立话题。
- AI 终态回调链路整合：`finalize_sync_after_ai` 先补发工单信息（含锚点记录）再回帖结果，并把解析后的真实场景传给回帖；`_finalize_sync_publish_after_ai` 及 5 处终态调用点透传任务 ID、结果载荷与失败原因。
- `TicketSyncNotifyService.build_ai_result_reply_content`：回帖模板渲染（成功/失败双默认模板，AI 变量含列表转行文本）。
- 飞书应用发送防御：响应缺失 `message_id` 时不再计入成功计数并记录 error 日志（防止"发送成功但锚点丢失"静默发生）。
- 手动分析请求模型新增 `aiResultFollowUp` 三态参数并随任务上下文快照持久化。

## 验证情况

- 单元测试 30 个（`tests/test_ticket_ai_result_follow_up.py`）：sendOn 四枚举矩阵、手动三态覆盖、task_id 幂等（含 50 条上限）、无锚点跳过、多群去重、单群失败不中断、成功/失败/自定义模板渲染、列表变量转行、无锚点策略分叉（skip 不补发 / send_then_reply 补发后回帖 / 补发被拦跳过 / 补发后仍无锚点跳过）、补发判定链（范围不匹配 / 场景开关未启用 / 已发送过不重复 / 推送条件拦截 / 发送无成功计数）。
- dev 环境端到端实测：真实发送工单信息消息 → 记录话题锚点 → AI 结果回帖挂到同一话题（`reply_in_thread`），全链路通过；消息格式含结论/根因/修复建议/置信度/相关文件/后续步骤。

## 注意事项

- 生效前提：发送模式为 feishu_app 或 hybrid；工单已通过自动/手动群推送在群里建立话题。
- 历史已推送但无锚点记录的工单（2026-09-04 至 2026-09-07 期间的部分数据）无法回帖，属于一次性数据缺口，新数据不受影响。
- 回帖使用飞书应用身份（与工单信息推送一致），机器人的 webhook 渠道不参与回帖。
