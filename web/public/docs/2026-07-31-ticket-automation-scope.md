# 工单自动化关注范围实施说明

## 目标

飞书多维表格可放开模块过滤，让外部模块修正能够同步回本系统；系统仍保存所有工单，但只对关注模块执行消耗 Token 或发送自动消息的能力。

## 配置

入口：`工单管理 -> 工单同步配置 -> 自动化关注范围`。

配置保存在 `ticket.sync.automation.automationScope`：

```json
{
  "enabled": true,
  "moduleIds": [1001],
  "moduleCodes": ["mod-proj-pos"],
  "moduleNameIncludes": ["POS", "收银"],
  "applyToStatisticsDefault": true
}
```

- `moduleIds`：系统模块 ID 精确匹配。
- `moduleCodes`：系统模块 Code 精确匹配，不区分英文大小写。
- `moduleNameIncludes`：系统模块名称包含任一关键字即命中，适合 `POS-*` 这类名称族。
- 模块 ID、模块 Code、模块名称关键字任一命中即可进入关注范围；启用后未配置三类条件时不限制模块，保持全量自动化行为。
- 关闭 `enabled` 时保持历史行为，所有模块都允许自动化。

## 同步与自动化行为

每次同步在外部字段映射完成后，按当前系统模块重新判定范围，并将结果写入：

```text
ticket.extra_data.automation_scope
```

记录包含 `eligible`、命中方式、命中关键字、当前模块和判定时间，可用于排查“为什么没有走 AI/自动推送”。

范围外工单仍会执行：

- 基础同步入库、原始载荷和外部字段快照更新；
- 项目、模块、状态、人员等常规字段映射更新；
- 外部字段到工单类型的映射分类。

范围外工单会跳过：

- 标题 AI、翻译、AI 统一字段提取、AI 工单分类；
- 自动拉取日志、自动创建 AI 分析任务；
- 自动向量刷新；
- 自动群消息推送（包括 AI 完成后的补发）。

手动群消息入口不受本门禁影响，仍代表用户的明确发送操作。

## 群推送条件

既有 `groupPush.autoPushCondition` 的配置、语法和判断逻辑没有改动。自动群推送顺序变为：

```text
当前模块关注范围判定 -> 原有 autoPushCondition -> 原有场景开关、发布状态与幂等判断 -> 发送
```

因此范围外工单不会进入原有推送条件判断；范围内工单继续按原条件配置发送。

## 统计口径

工单统计页新增“数据范围”切换：

- `关注范围`：默认值。启用 `automationScope` 且 `applyToStatisticsDefault=true` 时，仅统计关注模块。
- `全部数据`：显式传 `automationScopeOnly=false`，统计系统中所有模块。

统计后端会解析模块 ID、模块 Code 和模块名称关键字。实时统计和快照统计同时按已解析模块 ID或原始模块名称关键字过滤，因此历史工单尚未映射 `module_id` 时，`POS` 这类名称关键字仍可命中；模块 Code 由系统模块表解析为对应 ID。若选择快照口径但时间范围内尚未生成快照，仍会返回空数据，应切换实时口径查看历史工单。

## 权限

“自动化关注范围”没有独立的 admin 判断，它与整个“工单同步配置”页面共用 `ticket:sync:config:list` 和 `ticket:sync:config:edit` 权限。开发环境当前只有“管理员(manager)”角色分配了这三个菜单项；需要其他角色维护时，在角色菜单中授予“工单同步配置”及其查询/保存权限即可。

## 历史修复建议

功能上线后，可自行移除飞书主动拉取任务中的模块过滤，设置历史更新时间范围并启用 `forceSync` 后补拉。每条历史记录同步时都会按最新外部模块重新映射和重新判定关注范围；范围外记录不会触发 AI 或自动群推送。
