# mitmproxy 抓包与 Mock 使用说明（桌面客户端）

> 适用范围：桌面客户端（client_new）「抓包测试」页。本文档说明该页面的功能、入口、全部配置项及常见问题。

## 功能概述

本页面内置 mitmproxy 代理内核，提供以下能力：

1. **流量抓包**：实时捕获经过代理的 HTTP/HTTPS 请求与响应，在列表中展示方法、域名、路径、状态码、耗时、大小和 Content-Type，点击行查看完整请求/响应详情。
2. **指定进程拦截（local 模式）**：不修改系统代理，直接按进程名（如 `CPOS-DF.exe`）透明拦截目标应用的流量，其他应用完全不受影响；也支持 regular（系统代理）、socks5 等其他模式。
3. **Mock 探测**：请求发出前先 POST 到配置的 Mock 服务器探测规则，未命中（响应 505 或超时）则自动放行真实请求。
4. **断点拦截**：命中关键字的请求/响应会暂停等待人工处理，可在界面上修改方法、URL、请求头、Body、状态码后放行。
5. **请求/响应延迟**：按路径对请求或响应注入固定延迟，用于弱网与超时场景测试。
6. **mitmweb 模式**：可切换为 mitmproxy 官方 Web 界面查看流量（默认仍同步显示到客户端列表）。

## 入口

桌面客户端 → 左侧导航「mitmproxy」页（**需要先安装「抓包代理」插件，未安装时该菜单不显示**）→ 顶部「启动 / 停止」控制代理运行，「设置」打开配置弹窗。

页面顶部信息栏显示：状态徽章、启动方式、记录数、模式快捷切换；代理端口 / Web 端口不再在页面顶部展示（在「设置」中查看和修改）。模式与运行方式的完整说明收纳在信息栏右侧的「**?**」按钮中，点击弹窗查看。

## 首次使用提示

首次使用时证书状态会显示"未找到 mitmproxy CA 证书"——**这是正常现象**：证书文件在**首次启动代理时**才自动生成。请先点击「启动」运行一次代理，之后证书状态会变为可安装，再点击「安装当前用户证书」完成信任。

## 窗口显示

客户端启动时主窗口自动最大化显示，适配笔记本等小屏幕。

## 配置项说明

「设置」弹窗按「基础配置 / Mock 与请求改写 / 过滤与拦截 / 延迟设置」分组展示；带开关的配置项（断点、包含、排除、流量过滤、Mock、延迟）开关与内容输入框在同一行，勾选开关后填写内容即可。每个配置项的标签旁有一个「**?**」图标，点击即可查看该字段的格式说明与默认值；输入框为空时占位提示也会显示期望格式。

### 基础配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 代理端口 | 9080 | 本地代理监听端口（127.0.0.1） |
| Web 端口 | 9081 | mitmweb 模式的网页端口 |
| 流量记录上限 | 500 | 列表最多保留条数，超出自动丢弃最旧记录 |
| 启动方式 | dump | dump=客户端内展示（web 相关选项仅 web 模式下可勾选）；web=mitmproxy 官方网页界面 |
| 代理模式 | local | local=按进程拦截；regular=系统代理；另有 wireguard/socks5/dns |
| 拦截应用 | CPOS-DF.exe | 仅 local 模式显示：要拦截的本机应用进程名，如 `CPOS-DF.exe`；支持手动输入，点击输入框自动加载系统进程列表供下拉选择，「加载」按钮可手动刷新 |
| 忽略 SSL 校验 | 开 | 对上游服务器的证书不做强校验（解密 HTTPS 必须开启） |
| 配置目录 | ~/.mitmproxy | mitmproxy CA 证书与配置所在目录 |
| 证书路径 | 空 | 自定义 CA 证书位置；留空时使用配置目录下的 `mitmproxy-ca-cert.cer`，输入框占位提示会显示当前实际生效的证书路径 |
| 脚本路径 | 空 | 自定义 mitmproxy 附加脚本（.py）路径，留空使用客户端内置脚本 |

### 路径匹配

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 启用断点拦截 | 关 | 开启后命中"断点接口"的流量暂停等待放行 |
| 断点接口 | 空 | 接口关键字（包含匹配），逗号/换行分隔多个 |
| 启用包含规则 | 关 | 开启后仅"包含路径"中的路径参与 mock |
| 包含路径 | 空 | 路径关键字列表 |
| 启用排除规则 | 关 | 开启后"排除路径"中的路径不参与 mock |
| 排除路径 | 空 | 路径关键字列表 |
| **过滤静态资源流量** | **开** | 命中"过滤路径"规则的请求**完全放行**：不记录到列表、不参与 mock、不参与断点与延迟。用于系统代理模式下避免静态资源等无关流量拖慢代理与界面 |
| **过滤路径** | `.png,.jpg,.jpeg,.gif,.webp,.bmp,.ico,.css,.js,.map,.woff,.woff2,.ttf,.otf,.eot,.svg,.mp4,.mp3,.webm,.avi` | 规则按逗号或换行分隔；**以 `.` 开头按路径后缀匹配（忽略大小写、不含 query）**，否则按路径**子串**匹配。示例：`/health` 会过滤 `/act/health/detail`；`.js` 不会误伤 `/api/login.jsdata`（非结尾） |

注意：过滤在规则命中时是"整条流量放行"，如果你需要 mock 某个静态资源或观察某个静态请求，请把对应后缀/路径从过滤规则中移除，或直接关闭该开关。

### Mock 与请求改写

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 启用 mock | 关 | 开启后所有（未被过滤/未被 include-exclude 拦下的）请求先探测 mock 服务器 |
| Mock 服务器 | 内部测试地址 | mock 规则服务地址，未命中返回 505 视为放行 |
| 附加请求头 | 空 | `k=v` 每行一条，随探测请求一并发送 |
| 附加 Body | 空 | `k=v` 每行一条，合并进探测请求的 JSON 或表单 |

### 延迟配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 启用请求延迟 / 秒数 / 路径 | 关 / 0 / 空 | 命中路径的请求发出前等待指定秒数 |
| 启用响应延迟 / 秒数 / 路径 | 关 / 0 / 空 | 命中路径的响应返回前等待指定秒数 |

## 使用步骤

1. 首次使用先在设置中确认证书目录，点击「安装证书」把 mitmproxy CA 安装到 Windows 信任根（HTTPS 解密必需）。
2. local 模式下填写目标进程名；regular 模式下启动后自行设置系统代理为 `127.0.0.1:代理端口`。
3. 点击「启动」，列表实时出现流量；顶部工具条支持按 URL/方法/状态/Content-Type 筛选与"只看失败请求"。
4. 需要 mock 时开启 mock 开关并配置 Mock 服务器与 include/exclude 规则；需要改包时开启断点并填写接口关键字，命中的行会出现「放行」按钮，点击后可在弹窗中编辑请求/响应再放行。
5. 断点暂停超过 180 秒未处理会自动放行，避免目标应用长时间挂起。

## 性能说明

- 流量列表刷新采用**定时批量渲染**（每 250ms 一批），高频流量下界面不再逐条刷新导致卡顿；**断点流量不受批量影响，立即显示并可立即放行**。
- 系统代理模式下建议保持"过滤静态资源流量"开启；被过滤的流量在服务端正常返回，只是不进入客户端列表，目标应用无感知。

## 常见问题

- **首次使用提示"未找到 mitmproxy CA 证书"？** 先点击「启动」运行一次代理，证书文件会自动生成，然后点击「安装当前用户证书」。
- **开启过滤后列表里看不到图片/JS 请求？** 这正是过滤生效的表现，关闭"过滤静态资源流量"或编辑过滤路径即可恢复。
- **HTTPS 显示证书错误？** 先安装 CA 证书；若目标应用做了证书锁定（certificate pinning），MITM 工具均无法解密该应用流量。
- **local 模式启动报"Cannot spawn more than one local redirector"？** 客户端启动前会自动清理残留的 windows-redirector 进程；若仍出现，请在任务管理器结束所有 `windows-redirector` 进程后重试。
- **断点放行按钮点了没反应？** 确认代理处于运行状态；断点暂停 180 秒后会自动放行，列表状态文本会标注原因。
- **左侧菜单没有「mitmproxy」？** 需要在主界面右上角「插件」中安装「抓包代理」插件并重启客户端。
