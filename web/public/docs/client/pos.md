# POS 页面使用说明

POS 页面用于批量管理测试机上的 POS 客户端：扫描发现 POS 程序、启动/停止、查看环境、在线切换机台、维护操作（清缓存/驱动/证书）等。

## 入口

客户端左侧导航「POS」页。

## 功能与使用

### 扫描 POS

1. 点击工具栏「工作目录」，添加 POS 程序所在目录（可用"添加目录"按钮选择或手输）；
2. 配置扫描模式：
   - 文件名模式：匹配的文件名，默认 `cpos-df.exe`；
   - 目录名模式：递归时只进入匹配的子目录，默认 `*`；
   - 递归深度：从工作目录向下最多进入几层，默认 1（只扫工作目录本身一层）；
3. 保存后点击「扫描」，结果列表展示所有匹配的 POS 完整路径，同时作为历史记录持久化。

### 启动 POS

点击每行的「启动」按钮。启动前会自动执行检查流程：

1. 检查 POS 文件是否存在；
2. 检查 POS 目录的 `pos.ini`（环境标识文件）。**缺少 pos.ini 或未配置 pos_env 时会直接报错并停止启动**——此时环境完全未知，启动出来的 POS 不可用；
3. 停止正在运行的 CPOS 进程（注意：此步在后续确认弹窗之前执行，若你在确认弹窗点了取消，原运行中的 POS 已被停止）；
4. 按情况弹确认框：
   - 没有本地业务参数（pos_params 文件）：确认后可直接启动；
   - 没获取到服务端配置：确认后可直接启动；
   - 本地与服务端配置不一致：可选"确定"（原样启动）或"切换后启动"（先调用在线切换再启动，切换后以服务端参数为准）；
5. 检查通过后按「启动前」勾选执行前置动作，最后以独立进程拉起 POS。

启动前勾选项说明：

| 勾选项 | 作用 | 依赖 |
| --- | --- | --- |
| 备份支付配置 | 备份 POS 支付驱动到备份目录 | 无 |
| 替换证书 | 把 mitmproxy 证书追加进 POS 的 certifi/cacert.pem | 需要 mitm 证书已存在 |
| 切换本地环境 | 预留勾选，启动流程暂不消费 | — |
| 切换云端POS | 启动前调用服务端接口切换机台 | 需要本地 pos_params；缺少时会弹确认框，可选择"跳过该动作并继续启动" |
| 清缓存 | 删除 POS 目录下的缓存文件（pos_params、init_config.data、charge_db） | 无 |
| 覆盖驱动 | 用 mock 支付驱动覆盖 POS 的 drive 目录 | mock 驱动源见下文"支付 mock 驱动" |
| 退出登录 | 启动前退出 POS 收银员账号 | 需要本地 pos_params；缺少时同"切换云端POS"处理 |

### 停止

- 「停止POS」：停止所有 POS 相关进程（CPOS-DF、Launcher、df_sv 等）；
- 「停止离线」：停止离线 java 进程。

### 查看环境 / 本地环境

- 「查看环境」：显示该 POS 的环境摘要（来源、商家、门店ID、环境、版本、POS号）；
- 「本地环境」：切换 POS 本地环境（基于 pos_env_back 备份目录），切换前会先停止 CPOS 进程。

### 在线切换 / 切换POS

- 行内「在线切换」：按本地 pos_params 信息调用服务端接口切换该机台；
- 工具栏「切换POS」：手动指定环境/商家/门店/MAC/POS_ID 进行切换，表单状态会自动记住。

### POS账号处理

退出收银员账号、重置收银员密码（调用服务端接口）。

### 维护操作（更多操作菜单）

- 清缓存 / 备份驱动 / 恢复驱动 / 覆盖驱动 / 清理环境文件 / 替换证书 / 复制路径。

### 同步配置

从远端地址拉取 POS 配置（服务地址、商家配置、环境文件清单等）并合并保存。新机器部署时推荐先"同步配置"而不是手动填写。

## POS 设置（工具栏「设置」）

- **服务地址**：POS工具Test/UAT、POS Test/UAT/生产五组地址。保存后立即生效，无需重启。未配置对应地址时，相关远程操作会明确提示"服务地址未配置"；
- **驱动目录**：
  - 支付MOCK驱动包目录：填包含 `drive` 和 `mock` 两个子目录的**包根目录**；留空用应用根目录下的 `payment_mock` 包；
  - 支付驱动备份目录：备份支付驱动的存放目录，留空（或目录不存在）用 POS 目录下 `drive_backup`；
- **环境文件清单**：启动前备份/本地环境切换时按此清单处理，默认 `database, log, pos_params, init_config.data, charge_db`；
- **缓存文件清单**：清缓存时按此清单删除，默认 `pos_params, init_config.data, charge_db`；
- **环境分组**（env_group_vendor）：环境 key 到商家列表的映射，JSON；
- **商家配置**（vendor_config）：商家账号、分辨率、自定义请求头，JSON；
- **配置拉取**：默认拉取地址，供"同步配置"使用。

## 支付 mock 包

「覆盖驱动」使用支付 mock 包，配置项填**包根目录**，包内放两个子目录：

```
payment_mock/            <- 配置项填这一层
├── drive/               <- 复制到 POS安装目录\drive\（同名覆盖、原有其他文件保留）
│   └── DF_pay_dll/...
└── mock/                <- 复制到 POS安装目录根（同名覆盖、原有其他文件保留）
    └── config.ini ...
```

覆盖规则：两个子目录都可选（包内至少要有其中一个）；复制时只覆盖同路径同名文件，POS 原有的其他文件一律不动。

取值优先级：

1. POS 设置里的「支付MOCK驱动包目录」（`payment_mock_driver_path`）；
2. 未配置时使用应用根目录下的 `payment_mock` 包。

「备份驱动」只备份 `drive` 内的同名文件（mock 写入根目录的文件不备份、不回滚）。备份存放位置取值优先级：

1. POS 设置里的「支付驱动备份目录」（`payment_driver_back_up_path`，目录需已存在）；
2. 未配置或目录不存在时使用 POS 目录下的 `drive_backup`。

「恢复驱动」把备份目录内容复制回 POS 目录下的 `drive`。

## 配置文件位置

所有配置保存在**应用根目录**的 `storage/data/` 下（打包版即 exe 所在目录），日志在应用根目录 `logs/` 下。无论从哪个目录启动程序（快捷方式、脚本、计划任务），配置和日志位置都固定不变。

配置文件说明：

| 文件 | 内容 |
| --- | --- |
| config_pos.json | POS 主配置：服务地址、商家配置、环境/缓存文件清单等 |
| config_pos_start.json | 启动前勾选项状态 |
| config_search.json | 工作目录与扫描模式 |
| config_search_result.json | 扫描历史 |
| pos_change_state.json | 切换POS表单状态 |
| pos_tool_ini_data.json | POS工具接口缓存（环境/门店列表） |

注意：配置文件损坏（JSON 格式错误等）时，相关功能会明确报错提示"配置文件异常:<路径>"，**不会**静默用默认值覆盖。修复方式：改正文件内容，或删除该文件（删除后下次使用会以默认值重建）。

## 常见问题

**Q：启动时提示"POS 目录缺少 pos.ini"？**
A：该 POS 目录缺少环境标识文件 pos.ini 或其中没有 pos_env 键。POS 程序包自带该文件，缺失说明目录不完整，请重新部署 POS 程序包。

**Q：启动时提示"没有本地配置和服务端配置"？**
A：POS 目录没有 pos_params 文件且服务端也没查到该机台信息。确认继续启动出来的 POS 没有业务参数，一般仅用于特殊排查场景；正常使用请先完成机台切换让服务端登记该机台。

**Q：提示"缺少本地POS参数（pos_params），无法执行【切换云端POS/退出登录】"？**
A：这两个启动前动作需要从本地 pos_params 读取商家/门店/环境信息，当前 POS 缺少该文件。可选择跳过该动作继续启动，或取消后先执行一次在线切换/重新部署 POS。

**Q：提示"XX服务地址未配置"？**
A：对应环境的服务地址没配置。到「设置」里填写，或用「同步配置」从已知好机器拉取配置。

**Q：提示"配置文件异常"？**
A：对应配置文件内容损坏（可能是编辑时格式错误或磁盘问题）。按提示路径找到文件修正内容，或删除后重试（会以默认值重建）。配置不会因此被静默重置。

**Q：取消启动后原来的 POS 没了？**
A：启动检查流程会先停止运行中的 CPOS 进程再做后续确认，取消启动时状态区会提示"已提前停止运行中的POS进程"，属预期行为。重新点启动即可。
