# 2026-06-20 工单日志查看弹窗全屏与 ticket_id 修复

## 结论
- 工单日志查看弹窗改为全屏展示，标题直接显示工单号与工单标题。
- 日志查看弹窗顶部原有基础信息与旧“入库内容/原始文档”查看区已去掉，统一保留 2026-06-19 新增的专用日志搜索/异常提取/上下文查看能力。
- 异常提取记录点击与上下文上一段/下一段因 `ticket_id` 缺失报错的问题已修复。

## 本次前端改动
- 文件：`web/src/views/ticket/index.vue`
- 调整点：
  - 日志查看弹窗从普通 `el-dialog` 改为 `fullscreen`。
  - 标题改为 `日志查看 - {ticketNo} - {title}`，去掉弹窗顶部基础信息描述区。
  - 去掉旧的“入库内容 / 原始文档 / 本地过滤关键字 / 查看入库内容”这套旧查看能力，只保留统一日志查看器。
  - 工单列表、工单详情日志拉取列表中的“查看日志”统一进入新的日志查看器。
  - 关键词输入框与“搜索”按钮放在同一行；时间输入框与“按时间”按钮也保持同一行。
  - 异常提取提示只展示总数，不再展示异常类型分布摘要。
  - 从日志拉取记录进入查看器时保留原记录 ID，避免后续“重新拉取 / 重新下载 / 重新截取”动作丢上下文。

## 本次接口参数修复
- 文件：`web/src/api/ticket/ticket.js`
- 调整点：
  - `GET /ticket/logs/files` 改为传 `ticket_id`。
  - `GET /ticket/logs/context` 增加 `ticketId -> ticket_id` 兼容转换。
- 原因：
  - 这两个接口在后端控制器中使用的是显式查询参数 `ticket_id`，不是请求体模型。前端此前传 `ticketId` 时，FastAPI 不会自动映射，导致上下文翻页等请求报“ticket_id缺失”。

## 影响范围
- 工单列表页操作列“日志”按钮。
- 工单详情页“日志拉取”页签中的日志记录列表“查看日志”按钮。
- 日志查看弹窗中的：
  - 关键词搜索；
  - 时间搜索；
  - 异常提取；
  - 上一段 / 下一段上下文翻页；
  - 重新拉取 / 重新下载 / 重新截取动作。

## 风险说明
- 旧“日志内容弹窗”中的入库文本直出能力已从当前页面移除；如果后续仍有业务明确依赖“直接查看入库压缩文本”，需要重新评估是否拆成独立入口，而不是继续和统一日志查看器混用。
- `GET /ticket/logs/files` 当前前端暂无明显使用入口，但已一并修正参数命名，避免后续接入时再踩同类问题。

## 验证建议
- 工单列表点击“日志”，确认弹窗全屏、标题包含工单号与标题。
- 工单详情页日志拉取列表点击“查看日志”，确认直接进入统一日志查看器。
- 搜索关键字、按时间搜索、异常提取后点击任一记录，确认不再出现“ticket_id缺失”。
- 在上下文区点击“上一段 / 下一段”，确认能继续翻页。
