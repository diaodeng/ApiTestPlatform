# 日志拉取

## 功能概述

日志拉取用于从外部平台获取指定门店/POS 的日志或数据库压缩包，支持下载归档、日志内容截取入库和自动 AI 分析。

## 入口

- **独立页面**：日志拉取管理 → 可创建不关联工单的独立拉取记录
- **工单详情**：日志拉取 Tab → 创建关联工单的拉取记录

## 使用方式

1. 点击「新增拉取」按钮
2. 选择或搜索关联工单（可选）
3. 选择环境分组（如 prod / uat）
4. 选择商家，系统会根据环境分组和商家自动匹配子环境及凭证：
   - **生产环境（prod）**：所有商家自动匹配，无需额外选择
   - **UAT 环境（uat）**：不同商家属于不同子环境（uat1/uat2/uat3），选商家后自动匹配
5. 选择门店、POS
6. 配置拉取方式（按时间或按路径）、数据类型（日志/DB）
7. 可选：开启「切日志」以指定时间范围截取入库
8. 可选：开启「自动AI」以拉取完成后自动触发 AI 分析
9. 配置存储方式（本地/FTP）和通知设置
10. 提交后记录状态为「待执行」，后台自动提交申请并进入轮询

## 记录状态说明

| 状态 | 说明 |
|------|------|
| 待执行 | 已创建，等待后台提交外部申请 |
| 提交申请中 | 正在向外部平台提交拉取申请 |
| 轮询处理中 | 已提交申请，等待外部平台生成压缩包 |
| 下载中 | 正在下载日志压缩包 |
| 解析中 | 正在解压并截取日志内容入库 |
| 成功 | 拉取完成 |
| 外部失败 | 外部平台返回失败 |
| 程序异常 | 内部流程异常 |
| 已取消 | 用户手动停止 |

## 执行机制

日志拉取采用「提交与轮询解耦」的架构：

- **提交申请**：创建记录后由后台线程池快速提交外部申请（瞬时完成，不长期占线程），成功后写入轮询截止时间
- **轮询探测**：由 Celery 周期任务「日志拉取周期扫描」批量扫描轮询中的记录，单次查询外部平台结果（任务键 `module_task.scheduler_maintenance.scan_log_pull_records`，需在「系统监控-定时任务」手动配置，建议每 30 秒执行）：
  - 命中可下载结果 → 投递下载解析
  - 外部返回失败 → 标记失败
  - 超过轮询截止时间（pollTimeoutSec，默认 1800 秒）→ 标记「轮询外部平台超时」失败
- **下载解析**：命中结果后由后台线程池下载压缩包并截取入库（短任务，不长期占线程）

因此任务提交与轮询探测**不受并发数限制**，可批量提交大量记录平铺消化；仅下载解析阶段复用线程池，并发不阻塞提交。

## 操作说明

- **查看日志**：成功/带内容的记录可查看截取的日志文本
- **复制**：复制已有记录的拉取参数快速创建新记录
- **停止**：停止正在执行中的任务（待执行/提交中/轮询中/下载中/解析中），停止后记录标记为「已取消」，保留已有进度，可重新拉取
- **重新拉取**：用原参数重新提交拉取任务
- **重新下载**：重新下载日志压缩包并覆盖原归档
- **删除**：删除记录并清理关联文件

## 配置项

日志拉取相关配置统一收纳在 **工单同步自动化 → 日志拉取配置** Tab 下，按作用域分为三组卡片：**拉日志默认值**、**存储与资源限制**、**日志拉取外部接口配置**。

### 拉日志默认值（提交参数默认值）

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| commandDataType | 默认数据类型（1=日志, 2=DB） | 1 |
| fileMaxSize | 单文件最大大小(MB) | 500 |
| zipMaxSize | 压缩包最大大小(MB) | 500 |
| storageMode | 默认存储方式(local/ftp) | local |
| rangeBeforeMinutes | 时间点前回溯分钟数 | 10 |
| rangeAfterMinutes | 时间点后延伸分钟数 | 10 |
| autoAiEnabled | 拉取成功后是否自动发起 AI 分析 | 关 |
| aiAgentCode / aiProviderCode | 自动 AI 分析使用的 Agent/Provider | 空 |

### 存储与资源限制（运行态护栏）

| 配置项 | 说明 | 默认值 | 范围 |
|--------|------|--------|------|
| maxWorkers | 日志拉取线程池最大并发数，保存后即时生效 | 2 | 1~20 |
| pollIntervalSec | 轮询探测间隔秒数 | 20 | ≥3 |
| pollTimeoutSec | 轮询超时秒数（超过则标记失败） | 1800 | ≥60 |
| downloadTimeoutSec | 单次 HTTP 下载超时秒数 | 300 | ≥30 |
| maxContentChars | 入库文本最大字符数，超出则失败 | 500000 | ≥10000 |
| maxExtractSeconds | 解压阶段最大耗时秒数 | 300 | ≥30 |
| maxExtractFileCount | 解压阶段最大文件数 | 2000 | ≥100 |
| maxExtractTotalBytes | 解压阶段最大总字节数 | 2147483648 | ≥10MB |
| maxSearchSeconds | 日志关键字搜索最大耗时秒数 | 30 | ≥3 |
| maxSearchFileCount | 日志搜索最大扫描文件数 | 1000 | ≥10 |
| maxPythonSearchBytes | Python 降级搜索最大扫描字节数 | 268435456 | ≥10MB |
| mode / localDirectory / ftp | 归档存储方式与目录/FTP 连接 | local | - |
| postDownloadExtractEnabled | 下载完成后自动解压到查看目录 | 关 | - |
| postDownloadVersionExtractEnabled | 解压后自动提取版本号 | 关 | - |
| postDownloadIndexEnabled | 解压后自动生成日志行索引 | 关 | - |

### 外部接口配置（环境分组）

| 配置位置 | 配置项 | 说明 |
|----------|--------|------|
| 日志拉取配置 → 外部接口 | 环境分组配置 | 多环境+子环境+商家映射+凭证绑定 |

### 外部接口配置（环境分组）

日志拉取的外部接口配置采用**环境分组 → 子环境 → 商家映射**三层模型，入口位于 **工单同步自动化 → 日志拉取配置** Tab 的「日志拉取外部接口配置」卡片。

**配置项说明：**

| 层级 | 字段 | 说明 |
|------|------|------|
| 环境分组 | 名称 | 用户可见的分组名，如"生产环境"、"UAT环境" |
| 环境分组 | 默认子环境 | 商家未匹配到任何子环境时的兜底选择 |
| 子环境 | 名称 | 如 UAT1、UAT2 |
| 子环境 | insertUrl | 日志录入接口地址 |
| 子环境 | pageUrl | 页面列表查询地址 |
| 子环境 | 凭证绑定 | 从统一凭证管理中选择的 HTTP Cookie/Header 凭证绑定 |
| 子环境 | origin | 请求 Origin 头 |
| 子环境 | 商家范围 | 选择"★ 全部商家"覆盖所有，或指定具体商家 venderNo |

**匹配规则：**
- prod 环境通常所有商家在同一个子环境，商家范围设为「全部商家」
- UAT 环境不同商家分布在不同子环境（uat1/uat2/uat3），分别配置商家范围和凭证
- 日志拉取时，用户只需选择环境和商家，系统自动匹配到正确的子环境和凭证
- 一个商家可能匹配到多个子环境，此时用户手动选择

**配置示例：**

```
gruop: "uat"
  ├─ uat1 → 凭证绑定A → 商家范围: [10001, 10002]
  ├─ uat2 → 凭证绑定B → 商家范围: [10003, 10004]
  └─ uat3 → 凭证绑定C → 商家范围: [10005]
```

## 注意事项

- 停止任务采用协作式取消，已在执行的 HTTP 请求可能需要等待当前步骤完成后才停止
- 停止后的记录仍可重新拉取
- 需要保证 Celery beat/worker 运行，且已在「系统监控-定时任务」手动配置「日志拉取周期扫描」任务（任务键 `module_task.scheduler_maintenance.scan_log_pull_records`，interval 30 秒），否则轮询中的记录不会被探测
- 服务重启后，轮询中/待执行的记录由周期任务继续处理，不会丢失；下载/解析中断的记录会清理为失败
- 删除记录会同步清理本地/FTP 上的归档文件
