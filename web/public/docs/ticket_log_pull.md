# 日志拉取

## 功能概述

日志拉取用于从外部平台获取指定门店/POS 的日志或数据库压缩包，支持下载归档、日志内容截取入库和自动 AI 分析。

## 入口

- **独立页面**：日志拉取管理 → 可创建不关联工单的独立拉取记录
- **工单详情**：日志拉取 Tab → 创建关联工单的拉取记录

## 使用方式

1. 点击「新增拉取」按钮
2. 选择或搜索关联工单（可选）
3. 选择环境、商家、门店、POS
4. 配置拉取方式（按时间或按路径）、数据类型（日志/DB）
5. 可选：开启「切日志」以指定时间范围截取入库
6. 可选：开启「自动AI」以拉取完成后自动触发 AI 分析
7. 配置存储方式（本地/FTP）和通知设置
8. 提交后记录状态为「待执行」，后台自动提交申请并进入轮询

## 记录状态说明

| 状态 | 说明 |
|------|------|
| 待执行 | 已创建，等待后台提交外部申请 |
| 提交申请中 | 正在向外部平台提交拉取申请 |
| 轮询处理中 | 已提交申请，等待外部平台生成压缩包 |
| 下载中 | 正在下载日志压缩包 |
| 解析中 | 正在解压并截取日志内容入库 |
| 成功 | 拉取完成 |
| 外部失败 | 外部平台返回失败 |
| 程序异常 | 内部流程异常 |
| 已取消 | 用户手动停止 |

## 执行机制

日志拉取采用「提交与轮询解耦」的架构：

- **提交申请**：创建记录后由后台线程池快速提交外部申请（瞬时完成，不长期占线程），成功后写入轮询截止时间
- **轮询探测**：由 Celery 周期任务「日志拉取周期扫描」（每 30 秒，可在「系统监控-定时任务」管理）批量扫描轮询中的记录，单次查询外部平台结果：
  - 命中可下载结果 → 投递下载解析
  - 外部返回失败 → 标记失败
  - 超过轮询截止时间（pollTimeoutSec，默认 1800 秒）→ 标记「轮询外部平台超时」失败
- **下载解析**：命中结果后由后台线程池下载压缩包并截取入库（短任务，不长期占线程）

因此任务提交与轮询探测**不受并发数限制**，可批量提交大量记录平铺消化；仅下载解析阶段复用线程池，并发不阻塞提交。

## 操作说明

- **查看日志**：成功/带内容的记录可查看截取的日志文本
- **复制**：复制已有记录的拉取参数快速创建新记录
- **停止**：停止正在执行中的任务（待执行/提交中/轮询中/下载中/解析中），停止后记录标记为「已取消」，保留已有进度，可重新拉取
- **重新拉取**：用原参数重新提交拉取任务
- **重新下载**：重新下载日志压缩包并覆盖原归档
- **删除**：删除记录并清理关联文件

## 配置项

| 配置位置 | 配置项 | 说明 | 默认值 |
|----------|--------|------|--------|
| 日志拉取 → 存储配置 | pollIntervalSec | 轮询探测间隔秒数 | 20 |
| 日志拉取 → 存储配置 | pollTimeoutSec | 轮询超时秒数（超过则标记失败） | 1800 |
| 工单同步配置 → 拉日志默认值 | commandDataType | 默认数据类型（1=日志, 2=DB） | 1 |
| 工单同步配置 → 拉日志默认值 | fileMaxSize | 单文件最大大小(MB) | 500 |
| 工单同步配置 → 拉日志默认值 | storageMode | 默认存储方式(local/ftp) | local |
| 日志拉取 → 外部接口配置 | insertUrl | 外部提交地址 | - |
| 日志拉取 → 存储配置 | mode | 存储模式 | local |

## 注意事项

- 停止任务采用协作式取消，已在执行的 HTTP 请求可能需要等待当前步骤完成后才停止
- 停止后的记录仍可重新拉取
- 需要保证 Celery beat/worker 运行且「日志拉取周期扫描」任务已启用，否则轮询中的记录不会被探测
- 服务重启后，轮询中/待执行的记录由周期任务继续处理，不会丢失；下载/解析中断的记录会清理为失败
- 删除记录会同步清理本地/FTP 上的归档文件
