# 工单问题实例关联改造方案

日期：2026-08-21

## 1. 背景与目标

当前问题实例管理页面在绑定工单时要求输入数据库内部 `ticket_id`，问题详情中的首张工单也直接展示内部 ID。工单详情只能从相似工单中确认归因，无法直接搜索已有问题实例；工单列表已有多选能力，但没有批量归因入口。

本次目标：

- 用户侧统一使用业务工单号，不要求输入数据库 ID；
- 问题详情首张工单显示工单号；
- 问题管理页面使用轻量远程搜索绑定工单，不加载完整工单列表；
- 工单详情支持直接搜索并关联已有问题实例；
- 工单列表支持将当前页选中的多张工单批量归入指定问题实例；
- 保留相似工单“候选 + 人工确认”语义，不按相似度或工单分类自动强绑定；
- 批量归因默认不覆盖已有问题归属，显式允许重新归因时才转移。

## 2. 当前数据与流程

问题实例管理列表读取 `ticket_issue`，详情读取 `ticket_issue`、`ticket.issue_id` 对应的工单和 `ticket_relation` 补充关系。工单主归因由以下字段承载：

- `ticket.issue_id`：主问题实例；
- `ticket.issue_relation_type`：归因关系类型；
- `ticket.issue_confirmed`：是否人工确认。

工单类型、是否真实问题、根因分类、解决方式和细分问题属于工单自动分类维度，不等同于 Issue。相似工单检索只提供候选；用户确认后，系统才会复用或创建 Issue 并绑定工单。

数据库继续保留 `ticket_id`、`first_ticket_id` 作为内部稳定关联。接口和页面额外返回 `ticketNo`、`firstTicketNo`，不迁移主键字段。

## 3. 页面方案

### 3.1 问题管理页面

现有“绑定工单”区域改为工单号/标题远程搜索选择器，返回最多 20 条轻量候选，展示工单号、标题、状态、项目、模块和当前问题摘要。当前 Issue 下的已绑定工单继续使用表格展示，不新增全量可关联工单列表。

首张工单只展示 `firstTicketNo`，保留内部 ID 用于打开工单详情。

### 3.2 工单详情页

没有问题归属时显示：

- 新建问题实例并绑定；
- 关联已有问题。

已有归属时显示：

- 更换问题；
- 解除归因。

关联已有问题使用问题编号/标题远程搜索，优先限制当前项目和模块，并要求用户确认目标 Issue。

### 3.3 工单列表页

在问题实例管理和版本批量维护附近增加“批量关联问题”。操作范围为当前页已勾选工单。弹窗展示选中工单预览、目标 Issue 搜索、归因说明和“允许重新归因”选项。

## 4. 接口方案

### 4.1 工单候选搜索

```http
GET /ticket/issues/ticket-options
```

参数：

- `keyword`：工单号或标题关键字；
- `projectId`：可选项目限制；
- `moduleId`：可选模块限制；
- `limit`：返回数量，服务端限制为 1-20。

### 4.2 按工单号绑定

```http
POST /ticket/issues/{issue_id}/tickets/bind
```

请求示例：

```json
{
  "ticketNo": "TK202608210001",
  "relationType": "manual",
  "confirmed": true,
  "remark": "人工确认属于同一问题"
}
```

现有按工单 ID 的接口继续保留，以保证兼容。

### 4.3 批量绑定

```http
POST /ticket/issues/bind-batch
```

请求示例：

```json
{
  "ticketNos": ["TK202608210001", "TK202608210002"],
  "issueId": 987654321,
  "relationType": "manual",
  "confirmed": true,
  "allowReassign": false,
  "remark": "按筛选结果统一归因"
}
```

批量服务先全量校验，再在一个事务中更新：

- 工单或 Issue 不存在时整体失败；
- 跨项目默认拒绝；
- 已属于其他 Issue 时默认整体拒绝；
- `allowReassign=true` 才允许转移；
- 同一目标 Issue 重复绑定保持幂等；
- 目标和旧 Issue 的影响工单数各刷新一次；
- 不创建工单两两补充关系。

返回成功数、冲突数、缺失工单号、已转移工单号和受影响 Issue 摘要。

### 4.4 Issue 选择

工单详情和工单列表复用现有 `/ticket/issues/list`，通过 `keyword`、项目、模块和状态参数完成远程搜索，不额外复制 Issue 数据表。

## 5. 版本展示

不在 `ticket_issue` 增加单一版本字段。Issue 详情的关联工单表展示绑定工单已有的：

- 发生版本；
- 计划修复版本；
- 实际修复版本；
- 实际发版版本。

版本名称由版本中心 ID 反查。后续需要问题实例级版本生命周期时，再增加多版本关系表。

## 6. 权限与审计

单张绑定、详情关联和批量绑定统一复用现有 `ticket:issue:bind` 权限。问题搜索复用 `ticket:issue:list` 或 `ticket:issue:query`，不新增重复权限。

批量重新归因必须显式确认；绑定请求保留操作人和备注，并写入工单事件，便于追溯。

## 7. 验证计划

后端定向测试覆盖：

- 工单号候选查询；
- 按工单号绑定；
- `firstTicketNo` 返回；
- 多工单批量绑定；
- 重复绑定幂等；
- 已归因冲突整体拒绝；
- 允许重新归因后旧、新 Issue 计数正确；
- 跨项目拒绝；
- 事务失败不留下部分更新。

执行后端 compile/ruff/pytest 定向测试，前端执行语法检查和构建；同步更新用户文档、更新记录、Wiki 页面和 `wiki/log.md`。

## 8. 非目标

本次不实现：

- 按问题类型或相似度后台自动强绑定；
- 批量自动创建问题实例；
- 跨分页全量选择；
- Issue 单一版本字段；
- 删除或迁移内部工单 ID 主键关联。
