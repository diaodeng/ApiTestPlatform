# 工单轻量AI测试工作台

## 概述

轻量AI测试工作台用于对工单轻量 AI 能力做**手动试运行**：选择一张工单、一个 Provider 和模型，选定或临时修改提示词，然后执行测试并查看完整结果。

适用场景：

- 调整自定义提示词前，先在测试工作台验证效果，不影响线上工单；
- 对比不同模型对同一工单的提取、分类效果，辅助选择 Provider/模型；
- 排查某张工单提取结果异常时，复现模型原始输出与归一化结果。

测试范围是**轻量 AI 任务**（信息提取、分类统计、翻译、标题总结、知识提炼），不包含依赖 Codex Agent 的重型 AI 分析。

## 入口

菜单：**工单管理 → 轻量AI测试**（路由 `/aiTest`）。

需要权限 `ticket:ai:test:run`（菜单默认挂载该权限，由管理员在角色管理中分配）。

## 支持的任务类型

| 任务类型 | 说明 | 默认提示词模板 |
|---|---|---|
| 信息提取 | 从标题、描述和原始入参提取分类、门店、POS/SCO、日期和版本号 | `ticket_sync_extract_default` |
| 分类统计 | 输出问题性质、工单类型、细分问题等结构化分类字段 | `ticket_stat_classify_default` |
| 翻译 | 将工单标题和描述翻译为中文 | `ticket_translate_default` |
| 标题总结 | 根据工单描述生成简洁标题 | `ticket_title_summary_default` |
| 知识提炼 | 基于工单上下文提炼知识库案例结构化内容 | `ticket_knowledge_extract_default` |

## 使用步骤

1. **选择任务类型**：切换类型时会自动匹配该类型的默认提示词模板并回填编辑区。
2. **选择工单**：输入工单号或标题关键字远程搜索，选中后自动加载工单标题、描述和原始入参（可在"工单内容"折叠区查看）。
3. **选择 Provider**：下拉仅列出具备"工单轻量AI"用途的启用 Provider；切换后模型选项联动。
4. **选择模型**：留空使用 Provider 默认模型。
5. **选择提示词模板**：默认按任务类型过滤；选中后模板原文回填到下方编辑区。
6. **临时编辑提示词（可选）**：直接修改编辑区内容即可，本次测试按编辑后的内容执行；点击"清空编辑"恢复使用模板原文。**编辑内容不会保存到模板**，如需正式生效请在提示词模板管理中修改。
7. **执行测试**：查看结果面板。

### 信息提取专属选项

- **提取输入**：可选"含原始入参"（默认，与生产链路一致，会把工单 `raw_payload` 发给模型）或"仅标题+描述"。

## 结果面板说明

| 区块 | 含义 |
|---|---|
| 归一化结果 | 走生产同款归一化逻辑后的业务字段（如 `posNo/scoNo/logDate/store`），信息提取任务还包含机台编号校验告警 |
| 解析 JSON | 从模型输出中提取出的原始 JSON |
| 模型原始输出 | 模型返回的完整文本 |
| 实际请求提示词 | 本次发送的系统提示词和用户提示词，便于核对提示词变量渲染结果 |

其他信息：

- **告警**：信息提取任务会显示"模型POS与原文候选不一致"等机台编号校验告警（与生产审计中的 `machineNumberWarnings` 同源）。
- **耗时与 Token**：显示本次执行耗时和 Token 用量（输入/输出/总计）。
- **失败原因**：Provider 停用、提示词模板不存在、模型接口异常等都会在结果面板顶部以红色告警展示。

## 与生产链路的关系

| 行为 | 测试工作台 | 生产链路 |
|---|---|---|
| 场景开关（如 `bitablePullEnabled`） | 不检查，始终可执行 | 按 `ticket.sync.automation` 场景开关控制 |
| 提取缓存（sourceHash/promptHash） | 不读写 | 命中缓存时跳过模型调用 |
| 工单回写 | 不回写任何业务字段 | 提取/分类结果回填工单 |
| 审计记录 | 写入 `sys_ai_task_execution`，任务类型带 `_test` 后缀 | 任务类型为生产编码 |
| 机台编号归一化 | 与生产完全一致 | — |
| 提示词变量渲染 | 与生产完全一致 | — |

因此，测试工作台上的"归一化结果"即为生产链路在相同输入、相同提示词、相同模型下的预期回填结果（信息提取任务可用"仅标题+描述"或"含原始入参"两种口径对比）。

## 注意事项

- 测试会真实调用 Provider 接口并产生 Token 消耗，请注意成本。
- 临时编辑的提示词仅当次请求生效；要长期生效请到提示词模板管理更新模板（模板更新会改变 promptHash，使相关工单提取缓存自然失效并触发重新提取）。
- 知识提炼任务的上下文按生产口径从工单时间线构建，需要工单已有事件或消息时结果更完整。
- 工单搜索按编号、标题、描述、模块、分类、根因、解决方案字段模糊匹配，最多返回 20 条。

## 常见问题

**Q：为什么测试结果和生产提取结果不一样？**
A：常见原因有三种：① 生产的提取结果命中了旧缓存（工单源数据未变时不重新调模型）；② 两者使用的提示词版本不同（模板更新时间不同）；③ 测试选择了不同 Provider/模型。可在结果面板核对实际发送的提示词。

**Q：修改编辑区提示词后，为什么模板管理里的内容没变？**
A：编辑区是临时内容，只对本次测试生效，不会保存。正式修改请到提示词模板管理页面。

**Q：信息提取测试能带上原始入参吗？**
A：默认带上工单 `raw_payload`（与生产一致）；如只想验证标题+描述的提取效果，切换"提取输入"为"仅标题+描述"。
