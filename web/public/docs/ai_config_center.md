# AI 配置中心说明

## 入口

- 菜单：系统管理 → AI配置中心
- 路由：`/system/aiconfig`

## 页面用途

AI 配置中心用于统一维护工单重型 AI 分析（Codex Agent）运行参数，以及日志分析相关的默认行为。

页面当前只管理工单 AI 分析链路，不负责轻量翻译、知识提炼、分类统计等场景。

## 可配置项

### 1. Worker 与执行环境

| 配置项 | 含义 | 默认值 | 影响 |
|--------|------|--------|------|
| Worker 命令 | 本地 Agent 执行 AI 分析时使用的命令 | `codex exec` | 影响后台实际启动的 CLI 命令 |
| Worker 模型 | Worker 默认使用的模型 | 空 | 为空时使用 Provider 默认模型 |
| Worker 沙箱 | Worker 沙箱模式 | `workspace-write` | 影响 Agent 执行时的文件访问范围 |
| 超时时间（秒） | 单次 AI 分析总超时 | `1800` | 超时后任务会失败并写入原因 |
| 工作区根目录 | 分析任务工作区根目录 | 空 | 决定任务日志、结果和上下文文件保存位置 |
| Agent 编码 | 优先投递的 Agent 编码 | 空 | 为空时系统会自动选择可用 Agent |
| Agent 并发数 | 单个 Agent 同时允许执行的 AI 任务数量 | `1` | 超过上限的任务会进入队列等待，直到有空闲槽位 |

### 2. 日志分析行为

| 配置项 | 含义 | 默认值 |
|--------|------|--------|
| 日志分析模式 | 控制日志正文的使用方式 | `digest` |
| 窗口缺失策略 | 时间窗口模式下日志正文缺失时的兜底方式 | `agent_extract` |

`digest` 只生成摘要，`full_directory` 生成完整目录，`hybrid` 同时生成摘要和完整目录。

`agent_extract` 表示由 Agent 本地截取日志，`server_extract` 表示由服务端截取。

## 队列说明

当单个 Agent 的“Agent 并发数”设置为 `N` 时，系统最多允许 `N` 个 AI 分析任务同时进入执行阶段。

超过上限的新任务不会直接失败，而是按提交顺序排队等待：

1. 任务先写入系统参数快照和 AI 任务表。
2. Worker 通过 FastAPI 网关进入 Agent 分发队列。
3. 若目标 Agent 当前已满员，任务保持等待。
4. 只要 Agent 仍在线，队列会在有空闲槽位时自动继续。

如果等待时间超过任务总超时，任务会失败并写入原因。

## 建议

- 生产环境通常建议先保持 `1`，确认 Agent 稳定后再逐步调大。
- 如果 Agent 机器资源较强、且 Codex 任务之间互不干扰，可以提高并发数。
- 如果出现 Agent 频繁断连或任务互相抢占工作区，优先把并发数调回 `1`。
