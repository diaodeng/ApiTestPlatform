# Web用例使用与录制说明

## 1. 功能概览

Web用例模块用于完成以下工作：

1. 维护 Web 自动化步骤（可视化编辑 + JSON 编辑）。
2. 执行单条或批量 Web 用例。
3. 录制页面操作并生成步骤。
4. 将录制结果保存为新用例、追加到已有用例、或覆盖已有用例。
5. 管理浏览器 Session 与 Cookie 配置，并在执行/录制时复用登录态。

支持浏览器：

- Chromium
- Chrome
- Microsoft Edge
- Firefox
- WebKit

---

## 2. 关键概念（先看这个）

### 2.1 Web用例

一个 Web 用例由基础信息（名称、浏览器、起始地址等）和步骤列表组成。

### 2.2 录制会话

录制会话是一次完整的录制过程，包含事件流、转换后的步骤、状态信息。录制结束后可以将结果落到用例。

### 2.3 状态来源（执行/录制通用）

状态来源有 3 种：

1. `不使用`：不使用 Session / Cookie。
2. `浏览器Session`：使用浏览器 Session 配置作为初始状态来源。
3. `Cookie配置`：使用 Cookie 配置（Runtime Profile）作为初始状态来源。

> 只能三选一（单选）。

### 2.4 保留浏览器状态

决定“执行/录制结束后是否保留最终状态”。

1. 关闭：不做状态更新/保存。
2. 开启：允许把结束时浏览器状态作为后续可复用状态。

### 2.5 自动同步状态

仅在“保留浏览器状态=开启”时可操作：

1. 开启：结束后同步到后端配置（入库）。
2. 关闭：仅本地保存，不入库。

---

## 3. 首次使用推荐流程

1. 新建一个 Web 用例（填用例名、起始地址、浏览器）。
2. 打开“录制”弹窗，设置录制参数并开始录制。
3. 停止录制后，选择“保存为新用例”或“覆盖到用例”。
4. 打开“执行”弹窗，执行该用例验证结果。
5. 在“执行记录”查看步骤明细和失败原因。

---

## 4. Web用例编辑

## 4.1 基础信息

在“新建/编辑用例”弹窗可维护：

1. 用例名称
2. 浏览器
3. 无头模式
4. 项目、模块
5. 起始地址
6. 说明

## 4.2 可视化步骤编辑（默认推荐）

步骤列表支持“按需编辑”：

1. 默认只展示文本，不是全量输入框。
2. 点击单元格后才进入编辑态。
3. 行点击只选中，不会自动弹“步骤详情”弹窗。
4. 启用/停用使用行内开关直接切换。
5. 操作列按钮为图标：前插、上移、下移、编辑、删除。

常用操作：

1. `新增步骤`：在尾部新增。
2. `编辑当前步骤`：打开详情面板做精细编辑（断言、定位器优先级等）。
3. 行内编辑：快速改动作、名称、定位、参数。

## 4.3 高级 JSON 编辑

提供“可视化步骤”和“高级 JSON”双向同步：

1. `应用 JSON 到可视化`：把 JSON 覆盖到步骤列表。
2. `使用当前可视化刷新 JSON`：从可视化生成 JSON。

## 4.4 常见动作与参数

支持动作包括：

1. 打开页面（`goto`）
2. 窗口最大化（`window_maximize`）
3. 设置窗口尺寸（`set_window_size`）
4. 点击/双击/悬停
5. 填写/清空输入
6. 键盘按键（`press`）
7. 勾选/取消勾选
8. 选择下拉项
9. 等待元素可见/隐藏
10. 固定等待
11. 页面/元素/标题/URL 断言

## 5. 执行用例

## 5.1 执行入口

1. 单条：用例行内点“执行”。
2. 批量：先勾选多条，再点“批量执行”。

## 5.2 执行参数说明

### 基础参数

1. `执行 Agent`：必填。
2. `浏览器`：本次执行浏览器。
3. `无头模式`：是否后台运行浏览器。
4. `每条后重启浏览器`：
   - 开启：每条用例独立浏览器。
   - 关闭：批量执行时尽量复用同一浏览器会话。

### 状态来源

1. `不使用`：不加载 Session/Cookie。
2. `浏览器Session`：可选具体 Session；不选也可继续执行（不阻断）。
3. `Cookie配置`：可选具体 Cookie 配置；不选也可继续执行（不阻断）。

### 状态保留

1. `保留浏览器状态`：控制执行结束后是否保留/更新状态。
2. `自动同步状态`：仅保留开启时可用，控制是否写入后端配置。

### 高级设置（默认收起）

1. `手动登录闸门`：给登录预留人工操作阶段。
2. `登录等待(秒)`：闸门开启且“登录后确认继续”关闭时生效。
3. `登录后确认继续`：先启动浏览器，用户确认后再继续执行。
4. `单步超时覆盖(ms)`：最小 500。
5. `步骤思考时间(ms)`：最小 0。

---

## 6. 录制 Web 步骤

## 6.1 录制入口

1. 关联用例录制：在用例行点“录制”。
2. 独立录制：点击“独立录制”。

## 6.2 录制参数说明

### 基础参数

1. `关联用例`：只读显示，独立录制时为“独立录制”。
2. `录制名称`：可空，空则自动生成。
3. `执行 Agent`：必填。
4. `浏览器`
5. `无头模式`
6. `起始地址`：必填。

### 高级设置（默认收起）

1. `状态来源`：同执行弹窗逻辑。
2. `浏览器Session / Cookie配置`：可选具体项，不选不阻断。
3. `保留浏览器状态`
4. `自动同步状态`
5. `窗口最大化`
6. `窗口宽度`、`窗口高度`
7. `停止时关闭浏览器`
8. `启用断言录制`
9. `断言归属方式`
10. `点击前自动断言`
11. `手动登录闸门`
12. `登录后确认继续`
13. `登录等待(秒)`

窗口参数规则：

1. 开启`窗口最大化`时，宽高输入忽略。
2. 未开启最大化时，宽高要么都不填，要么都为正整数。

## 6.3 录制中能力

1. 顶部工具栏：开始录制、停止录制、刷新详情、查看录制详情、保存为新用例、追加到用例、覆盖到用例。
2. 录制实时数据：
   - `步骤列表` Tab：查看实时步骤。
   - `步骤JSON` Tab：查看实时 JSON。
   - 步骤列表中的“删除”会同步删除当前录制会话对应事件，刷新后不会再出现，录制过程不中断。
3. 浏览器窗口动作支持：
   - 开始录制时可按配置自动设置最大化/尺寸。
   - 录制过程中手动最大化或调整尺寸，会自动记录为步骤（去重与防抖处理）。

## 6.4 录制结束后处理

1. `保存为新用例`：生成新 Web 用例。
2. `追加到用例`：追加到目标用例末尾。
3. `覆盖到用例`：替换目标用例原有步骤。
4. `回放录制`：直接按录制结果执行一次。

## 7. 状态来源与保留规则（重点）

以下规则适用于执行和录制：

## 7.1 选择 `不使用`

1. 不使用 Session/Cookie。
2. 不会更新或保存 Session/Cookie。
3. 自动同步状态不可操作且不同步。

## 7.2 选择 `浏览器Session`

1. 选择了具体 Session：执行/录制启动时使用该 Session。
2. 未选择具体 Session：启动时不使用 Session（流程不阻断）。
3. `保留浏览器状态=关闭`：结束后不更新 Session，不同步后端。
4. `保留浏览器状态=开启`：
   - 若已选 Session：结束后更新该 Session。
   - 若未选 Session：结束后自动新建 Session。
   - 是否入库由`自动同步状态`决定。

## 7.3 选择 `Cookie配置`

1. 选择了具体 Cookie 配置：启动时使用该配置注入 Cookie。
2. 未选择具体配置：启动时不注入 Cookie（流程不阻断）。
3. `保留浏览器状态=关闭`：结束后不更新 Cookie 配置，不同步后端。
4. `保留浏览器状态=开启`：
   - 若已选 Cookie 配置：结束后更新该配置。
   - 若未选 Cookie 配置：结束后自动新建 Cookie 配置。
   - 是否入库由`自动同步状态`决定。

## 8. Cookie配置管理（运行时配置）

入口：执行/录制弹窗中的“管理Cookie”。

主要字段：

1. `配置名称`（必填）
2. `是否启用`
3. `目标链路`（Web/API/Desktop）
4. `排序`
5. `项目(可选)`、`模块(可选)`
6. `运行覆盖(JSON)`：覆盖本次运行参数，如 `stepTimeoutMs`。
7. `变量(JSON)`：可在 Cookie 规则里用 `${var}` 引用。
8. `Cookie规则(JSON)`：核心注入规则。
9. `快速导入`：支持 Cookie / Set-Cookie / 请求头文本解析。
10. `状态作用域`：用于保留状态作用域管理（作用域 Key、匹配域名、启用状态等）。
11. `备注`

Cookie 规则示例：

```json
[
  {
    "name": "主站登录",
    "match": { "host": "example.com" },
    "applyOn": ["before_start", "before_step", "before_goto"],
    "cookies": [
      { "name": "token", "value": "${token}", "domain": ".example.com", "path": "/" }
    ]
  }
]
```

---

## 9. 浏览器Session管理

入口：执行/录制弹窗中的“管理Session”。

主要字段：

1. `Session名称`（必填）
2. `作用域Key`（必填）
3. `是否启用`
4. `绑定浏览器`（可选）
5. `项目(可选)`、`模块(可选)`
6. `排序`
7. `匹配域名`（逗号分隔）
8. `StorageState(JSON)`（cookies/origins）
9. `快速导入`：支持 storage_state JSON、Cookie、Set-Cookie 文本
10. `备注`

StorageState 示例：

```json
{
  "cookies": [],
  "origins": []
}
```

## 10. 执行记录与录制记录查看

### 10.1 列表排序

Web 用例、执行记录、录制记录默认按：

1. 创建时间倒序
2. 更新时间倒序

### 10.2 执行详情

1. 基础信息：执行记录ID、状态、时间、耗时等。
2. 失败信息：仅失败时展示异常提示。
3. Cookie 注入提示：仅状态来源为 Cookie 时展示。
4. 明细采用 Tab：
   - `步骤列表`
   - `步骤JSON`

### 10.3 录制详情

1. 基础信息：录制ID、名称、状态、Agent、浏览器、时间等。
2. 异常信息：有异常时显示。
3. 明细采用 Tab：
   - `步骤预览`
   - `原始事件`
   - `原始JSON`

## 11. 常见问题与排查

1. 录制无法启动：先检查是否已选择 Agent、是否填写起始地址。
2. 录制窗口尺寸报错：未开启“窗口最大化”时，宽高需同时填写正整数或同时留空。
3. 选择了 Session/Cookie 但没生效：
   - 检查状态来源是否选对；
   - 检查是否选择了具体配置项；
   - 检查配置是否启用、域名是否匹配目标站点。
4. 保留状态未入库：检查“保留浏览器状态”和“自动同步状态”是否都开启。
5. 看不到 Session 相关选项：通常是权限不足（`hrm:webCase:persistContext`）。
6. 批量执行登录确认只触发一次：这是预期行为，默认只在首条等待确认。

---

## 12. 实操建议

1. 首次搭流程时，先用录制生成主干步骤，再补充断言与异常分支。
2. 对高波动页面，优先使用更稳定定位器（Test ID / ID / Name / Role）。
3. 生产登录态建议：
   - 状态来源选 Session 或 Cookie；
   - 保留浏览器状态开启；
   - 自动同步状态按团队策略决定（共享入库或仅本地）。
4. 批量执行若想提速，可关闭“每条后重启浏览器”以复用浏览器上下文。
