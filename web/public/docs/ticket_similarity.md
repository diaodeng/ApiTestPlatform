# 相似工单与处理案例

## 功能说明

系统将相似检索拆成两类信息：

- **表现相似**：根据标题、描述和稳定症状召回，适合新工单刚入库时查找候选。
- **处理经验相似**：根据症状、证据、排查过程、根因、解决方案和验证方式召回，适合复用已形成的处理经验。

相似度只提供候选和分析依据，不会自动把工单归入同一个问题实例。问题实例仍需人工确认。

## Provider

入口：**工单管理 → 相似工单配置**。

- `Embedding`：生产推荐配置，调用外部 Embedding 服务，向量保存在 `embedding_record`。
- `local_hash`：本地测试方式，不依赖外部模型。
- `qdrant`：开发和后续扩展使用的可选 Provider，本次生产案例索引不依赖 Qdrant。

Embedding 配置中的**文本上限（字符）**用于防止向量化文本超过模型的上下文长度：拼接后的向量化文本超过该字符数时，会在请求外部接口前自动截断（0 表示不限制）。默认 12000 字符，以 `BAAI/bge-m3` 上限 8192 token 为基准留有中英混合文本的安全余量；更换其他模型时应按其上下文长度调整该值。截断优先压缩过长的描述类长文本，标题、AI 摘要等短字段保持完整。

修改模型、版本、维度或向量字段后，应执行向量重建。系统会根据内容哈希、模型、版本、用途和维度复用未变化的向量。

## 向量字段

表现相似默认使用：

- 标题；
- 描述；
- 稳定 AI 摘要；
- RCA 中的问题现象；
- 过滤后的重要关键词。

配置页面的向量化字段只展示以上 5 个实际生效的选项。工单号、状态、处理人、模块名称、分类、根因、解决方案和完整 RCA 不作为表现相似的默认文本；项目、模块、版本和环境作为结构化匹配信号使用，不强行拼入自然语言向量。

字段含义说明：

- **描述**：工单正文。外部同步工单若 AI 翻译成功，落库的是翻译后文本；
- **AI摘要**：AI 分析结论中的摘要段，仅执行过 AI 分析的工单才有；
- **RCA问题现象**：RCA 中记录的问题症状，尚未形成 RCA 时为空；
- **重要关键词**：工单标签。

## 结构化匹配

初次入库时系统会尽量提取环境、版本、错误码、Trace ID 和 Request ID。字段不完整不会阻止工单入库。

查询排序会综合：

- 向量语义分数；
- 错误码、Trace ID、Request ID 等精确命中；
- 标题和描述关键词重合；
- 项目、模块、版本和环境上下文；
- 案例是否已验证；
- 明确冲突信号的降权。

缺失字段不会自动判定冲突。明确不同的错误码、环境、项目或模块会在结果中标记为冲突。

## 案例生命周期

当 AI 分析或人工 RCA 形成根因、解决方案等有效结论后，系统创建 `draft` 案例并异步生成案例向量。

案例状态：

- `none`：尚未形成案例；
- `draft`：已有可沉淀结论，但尚未人工确认；
- `verified`：人工确认可以作为可复用处理经验；
- `rejected`：人工判断不适合复用。

进入工单详情的“处理案例相似”区域，顶部为**当前工单案例**区块，展示本工单案例的状态、版本、根因和方案摘要，以及案例向量索引状态。带有案例的工单可以在这里进行人工确认操作（需要 `ticket:similarity:case` 权限）：

- **确认案例**：将草稿案例确认为已验证案例。确认要求至少存在根因、解决方案，以及证据或验证方式，信息不足时按钮不可点击。确认后系统异步生成已验证案例向量。
- **回退草稿**：将已验证案例退回草稿状态，便于结论修订后重新确认。
- **驳回案例**：判定案例不适合复用时驳回，需要填写驳回原因；驳回后案例不再参与相似召回。

案例状态变化后，页面会自动刷新概览和相似工单结果。案例确认不等于问题实例归因，也不会自动修改 `ticket.issue_id`。案例内容发生变化后，已验证案例会回到草稿状态，避免旧结论继续作为高可信经验。

独立详情页（只读查看页）会展示当前工单案例的状态信息，但不提供确认、回退和驳回操作入口；案例人工确认请在工单列表的详情弹窗中进行。

## 评论和 AI 分析

普通评论不会单独触发向量化。评论中的错误码、日志证据、排查结论只有在被 AI 或人工纳入画像、RCA 或案例字段后，才会触发对应索引更新。

AI 分析会读取相似候选、消息、快照、日志和 RCA。相似工单用于逐条比较症状、证据、版本、环境、根因和方案，不根据相似度直接认定为同一问题。

## 性能和注意事项

生产无 Qdrant 时，精确信号使用 MySQL 普通索引，向量使用 MySQL 中保存的 JSON 向量分批扫描并在应用层计算余弦相似度。案例数量通常小于普通工单数量，因此只对存在有效结论的工单建立案例索引。

2026-09-07 起向量扫描做了两项优化（背景：曾因相似检索全量加载向量导致服务端内存压力和重启）：

- **信号预筛**：检索文本中出现错误码（如 `错误码: SG7E-3242`）、Trace ID、Request ID 时，先按精确信号索引筛出候选工单，再只对这些工单做向量比对。生产实测带错误码的检索从约 11 秒缩短到 0.2 秒内。可通过相似度配置 `signalPrescreenEnabled: false` 关闭（默认开启）；无法提取信号时自动退回全量扫描，不影响结果召回。
- **分页扫描**：向量比对改为按页（500 条/页）独立查询、逐页释放，替代旧的一次性全量迭代。每次检索的内存增量从约 30MB 降到 10MB 级，且不再随向量总量累积。

- 向量查询较慢时先减少召回数量并确认模型维度；
- 大批量历史数据使用后台重建，不要在业务高峰强制重建全部向量；
- 外部 Embedding 失败不会回滚工单、RCA 或 AI 结论，案例索引会记录失败原因并可重试；
- 工单描述或原始报文特别长时，向量化文本会按"文本上限"配置自动截断，不会导致外部接口报参数无效；
- 详情页显示的分数是综合分，不等同于"同一根因概率"；
- “归入同一问题”仍需人工确认。

## 接口

- `GET /ticket/{ticket_id}/similar-tickets?limit=5`：查询表现和处理经验候选；
- `GET /ticket/{ticket_id}/summary`：工单轻量概览，响应中包含当前工单自身的 `similarityCase` 案例摘要；
- `POST /ticket/{ticket_id}/similarity-case/status`：确认、驳回或回退案例状态。

案例状态接口需要 `ticket:similarity:case` 权限。
