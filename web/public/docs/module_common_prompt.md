# 模块通用提示词使用说明

## 功能用途

模块通用提示词用于维护某类模块在不同项目中都适用的工单 AI 分析说明。例如多个项目都存在“销售回传”模块，并且模块编码相同，可以为该编码维护一份通用的排查重点、业务规则和常见依赖，后续关联该编码的工单会自动加载这份说明。

项目自己的特殊链路仍维护在项目模块信息中，二者不会互相覆盖。

## 入口

- 菜单：**HRM → 模块通用提示词**
- 需要具备模块通用提示词的查询、新增、修改或删除权限。

## 新增和编辑

1. 点击“新增”，填写模块编码、通用说明、启用状态和备注。
2. 模块编码应使用 HRM 模块实际维护的业务编码，系统会自动去除首尾空格。
3. 通用说明填写跨项目都成立的内容，例如业务规则、上下游系统、关键接口、数据校验、常见故障表现和排查方向。
4. 点击保存后，后续新创建的 AI 分析任务会按当前配置读取该说明。
5. 编辑已有记录时模块编码不可修改；如果业务含义已经变化，应停用旧编码说明并按新编码建立记录，避免历史语义被静默改变。

## 字段说明

| 字段 | 说明 |
| --- | --- |
| 模块编码 | 跨项目复用的匹配键，必须与工单关联模块的 `module_code` 完全一致（首尾空格不参与匹配）。 |
| 通用说明 | 该编码适用于所有项目的 AI 分析说明，不能为空。 |
| 启用状态 | 启用后新任务会自动加载；停用后不再加载，但不会修改已创建的任务。 |
| 备注 | 供管理员记录适用范围、维护人或变更原因。 |
| 关联模块数/影响项目数 | 页面动态统计当前编码关联的模块和项目数量，修改或删除前请先确认影响范围。 |

## 提示词加载顺序

工单 AI 分析会按以下顺序组织默认说明：

1. 项目默认提示词；
2. 模块通用说明；
3. 当前项目模块说明；
4. 用户选择的通用追加提示词；
5. 本次分析临时说明；
6. 系统固定约束和输出格式。

工单详情的 AI 分析区域可以展开查看前三层是否命中及其内容。页面展示以后端实际解析结果为准，不会根据模块名称猜测通用说明。

## 数据维护注意事项

- 同一模块编码只有一份通用说明，修改会影响所有使用该编码的项目的新 AI 分析任务。
- 不同项目相同编码属于正常复用，不要为了消除重复而合并项目模块或修改历史工单关联。
- 项目内 `project_id + module_code` 应保持唯一。上线前应先执行只读盘点，处理重复编码和首尾空格后，再由数据库管理员执行联合唯一索引。
- 初次上线不会把某个项目的模块描述自动复制成通用说明。请先确认业务含义，再由管理员人工录入；项目专属内容继续保留在项目模块字段中。
- 历史 AI 任务保留创建时的提示词和快照，不会因后续修改、停用或删除通用说明而改变历史结果。

## 示例：销售回传

若项目 A 和项目 B 的模块都使用编码 `SALES_RETURN`：

- 在本页面创建一条 `SALES_RETURN` 通用说明，填写销售回传共有的接口、状态流转和数据校验规则；
- 在项目 A、项目 B 各自模块信息中分别填写项目特有的部署地址、依赖服务或差异化流程；
- 两个项目的新 AI 分析都会加载同一份通用说明，并继续追加各自的项目模块说明。

## 常见问题

### 停用后历史任务会怎样？

不会改变。停用只影响之后创建的分析任务；历史任务仍使用原始提示词快照。

### 关联模块数为零，可以先配置吗？

可以。模块通用说明按编码保存，允许先配置后创建或关联项目模块；待模块使用该编码后会自动显示关联数量。

### 为什么工单没有加载通用说明？

请检查工单是否关联了有效项目模块、模块编码是否为空或存在首尾空格，以及该编码的通用说明是否已启用。项目模块无效或编码不一致时，系统不会按模块名称猜测。
