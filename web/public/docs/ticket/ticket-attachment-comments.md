# 工单附件与评论来源扩展说明

本文档说明工单附件（多维表格附件字段）展示、一线回复评论、记录评论拉取三个功能的用途、配置与注意事项。

## 一、工单附件展示

### 功能说明

多维表格中"(IT)工单附件"、"(RD)答复附件"等附件字段，可通过主动拉取字段映射同步到本系统：

- **工单级附件**（映射目标字段 `ticketAttachments`，如"(IT)工单附件"）：展示在工单详情"概览"页的"工单附件"卡片，点击即可查看/下载。
- **评论级附件**（映射目标字段 `replyAttachments`，如"(RD)答复附件"）：随一线回复评论展示在评论下方。

### 链接机制（重要）

系统**只保存附件的 fileToken 和文件名、大小、类型**，不保存飞书返回的下载链接（该链接约 24 小时过期）。

用户点击附件时，由后端实时向飞书换取新的临时下载链接并 302 跳转，因此链接永远有效。换取的临时链接在后端有 30 分钟缓存以减少 API 调用。

### 使用前提

1. 在"同步自动化 → 主动拉取"的字段映射中，把多维表格附件字段映射到目标字段 `ticketAttachments` 或 `replyAttachments`；
2. 重新拉取（或等定时任务）后附件元信息入库；
3. 飞书应用需具备读取多维表格和云文档素材的权限。

### 接口说明

| 接口 | 说明 |
|---|---|
| `GET /ticket/{ticketId}/attachments` | 返回工单附件元信息列表（fileToken/name/size/type/来源字段） |
| `GET /ticket/{ticketId}/attachments/{fileToken}/url` | 302 跳转到飞书临时下载链接，可直接用于 `<img>` 或下载 |

## 二、一线回复评论（L1 Response）

### 功能说明

多维表格中"(IT) L1 Response"字段（一线回复内容）会像"排查过程"一样被解析为工单评论：

- 解析规则与排查过程一致：按 `YYYYMMDD负责人：内容` 的行格式分段，每段一条评论；
- 评论正文末尾自动追加 **【一线回复】** 标识文案，评论列表中同时显示绿色"一线回复"标签；
- 评论的 `sourceField` 为 `l1Response`，与排查过程（`stepReason`）的评论互相独立、互不覆盖。

### 使用配置

在"同步自动化 → 主动拉取"的字段映射中，把"(IT) L1 Response"映射到目标字段 `l1Response` 即可。

### 时间规则

分段行首的 `YYYYMMDD` 日期用于确定评论时间：

- **日期不是当天**：评论时间记录为该日期的 `00:00:00`（表格里只有日期、没有时刻）；
- **日期是当天**：不使用 00:00:00，评论时间直接采用同步入库的当前时刻（避免当天记录出现误导性的 00:00:00 时间）。

注意：已入库评论的时间不会随后续同步变化；跨天窗口（如 23:59 写入、00:01 后同步）按"非当天"处理。

## 三、多维表格记录评论拉取

### 功能说明

飞书多维表格中每条记录下方可以添加"评论"（记录自带评论，区别于字段内容）。本功能定期扫描本地已关联多维表格记录的工单，把记录评论同步为系统工单评论：

- 评论人显示为飞书用户姓名（通过 open_id 解析，失败时显示 open_id）；
- 评论时间使用记录评论的创建时间（精确到时分秒）；
- 评论中的图片/文件附件会一并保存（同工单附件机制，点击时实时换链）；
- 幂等同步：同一条记录评论不会重复创建，评论在飞书侧被编辑后再次同步会更新本地内容。

### 当前限制（重要）

截至 2026-09，**飞书开放平台服务端 API 尚未公开"记录评论"读取接口**（官方 SDK 1.4~1.6 的 bitable 资源清单与概览文档均无该 API，直接调用返回 404）。

因此该功能做了预留式实现：

- 功能默认关闭；
- 接口路径可通过配置指定，飞书 API 上线后把真实路径填入 `messageSync.bitableRecordCommentApiPath` 即可启用，无需改代码；
- 在 API 上线前开启开关，任务会正常运行但拉取到 0 条评论，日志中会提示"记录评论接口暂不可用"。

### 配置项

配置位于"同步自动化"的 `messageSync` 配置组：

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `syncBitableRecordComments` | false | 是否启用记录评论同步 |
| `bitableRecordCommentMaxTickets` | 200 | 单次任务最多处理的工单数（控制飞书 API 用量，上限 1000） |
| `bitableRecordCommentApiPath` | 空 | 记录评论 API 路径模板，留空使用内置预留路径；飞书上线后可覆盖 |

### 手动执行与定时任务

- 手动执行：调用 `POST /ticket/sync/automation/bitable-record-comments/run`（需要 `ticket:sync:config:edit` 权限）；
- 定时任务：任务名 `module_task.scheduler_maintenance.pull_feishu_bitable_record_comments`，支持任务参数 `maxTickets` 覆盖单次上限。

### 幂等机制

评论幂等键为 `sha256("bitable_comment|{记录ID}|{评论ID}")`，与数据库唯一约束 `(ticket_id, source_segment_key)` 共同保证不重复。

## 四、常见问题

**Q：附件点击后提示"附件临时链接获取失败"？**
检查飞书应用配置（appId/appSecret）是否有效、是否具备云文档素材读取权限；查看后端日志中"附件临时链接换取失败/异常"的具体原因。

**Q：为什么附件映射后工单上没有附件？**
附件元信息在记录同步入库时保存。若记录内容未变化，主动拉取会按快照跳过；可对单条工单强制重拉，或在多维表格中修改该记录触发更新。

**Q：一线回复评论时间和排查过程评论时间为什么有 00:00:00？**
表格中只写了日期没有时刻，历史日期按 00:00:00 记录；当天日期的评论直接用入库时间。
