# 工单 AI Token 用量记录与展示

## 变更概述

本次更新为工单 AI 分析补充了 Token 用量记录和展示能力，方便排查 AI 调用成本、比较不同 Provider/模型的开销，并把工单侧历史记录与系统侧 AI 审计串联起来。

## 用户可见变化

### 工单详情页

- 在 **AI任务历史** 中新增“输入 Token”“输出 Token”“总 Token”三列。
- 在 **AI任务原文** 弹窗中新增“审计ID”“输入 Token”“输出 Token”“总 Token”。
- 在顶部 **最新AI结论** 卡片中新增当前工单整单汇总：
  - AI任务数
  - 成功任务数
  - 输入 Token
  - 输出 Token
  - 总 Token

### AI 执行审计

- 在 **系统管理 → AI执行审计** 列表中新增“总 Token”列。
- 在审计详情中新增“总 Token”字段。
- 审计详情仍保留原始 `tokenUsage` JSON，方便和 Provider 原始返回内容对照。

## 统计规则

- 若 Provider 同时返回输入、输出和总量，则页面按原始值显示。
- 若 Provider 只返回总量，则只展示总 Token；输入 Token 和输出 Token 保持为空。
- 系统不会根据字符数或总量反推输入/输出，避免误导成本分析。

## 性能说明

- 工单概览中的累计 Token 统计只在 **当前工单详情概览** 接口内按 `ticket_id` 做一次数据库聚合。
- 工单列表、分页列表和批量摘要接口不做 Token 聚合，因此不会明显影响列表性能。

## 适用场景

- 对比不同 AI Provider 或模型的成本差异。
- 排查某张工单为什么 AI 调用次数多、消耗高。
- 从工单任务历史定位到 AI 执行审计详情，查看完整请求、响应和原始 Token 用量。
