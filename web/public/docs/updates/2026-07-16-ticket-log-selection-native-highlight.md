# 2026-07-16 工单日志选区候选词与非侵入高亮

## 背景

工单详情页日志查看器在 2026-07-15 将高亮词改为独立文本框维护，避免复制日志时因为选区触发状态刷新而丢失浏览器选区。本次需要恢复选中即生效的效率：用户在搜索结果详情中选中文本时，选中文案既要进入高亮候选词，又要立即高亮相同内容；取消选中时，只移除本次选区临时追加的高亮词。

## 实现

1. `useLogViewer` 新增选区临时高亮状态，区分手工输入高亮词和选区临时追加的高亮词。
2. 用户在日志上下文块中完成选中后，选中文案会写入高亮词文本框并立即参与当前上下文高亮。
3. 浏览器选区折叠或移出日志上下文块时，自动移除本次选区临时追加的高亮词；用户手工输入过的同名高亮词不会被误删。
4. 支持 CSS Highlight API 的浏览器使用 `CSS.highlights` + `Range` 做非侵入高亮；不支持时保留原 `<mark>` 拆分渲染兜底。

## CSS Highlight API 说明

非侵入高亮是指不把日志文本拆成多个 `<mark>` 或 `<span>` 节点，而是基于现有文本节点创建 `Range`，交给浏览器的 `CSS.highlights` 注册表绘制背景色。日志 DOM 保持原始文本结构，复制、选择和 Vue 更新的干扰更小。

在当前日志详情场景中，CSS Highlight API 正常路径更优：它减少 Vue 虚拟 DOM 节点数量和文本拆分成本，尤其适合上下文行数较多、多个关键字同时高亮的场景。回退方案仍只处理当前上下文块，不扫描整份日志。

## 影响范围

- 仅影响工单详情页日志查看器的搜索结果详情高亮。
- 不改变后端日志搜索、上下文读取和日志拉取接口契约。
- 不改变手工输入高亮词的持久方式；关闭查看器或点击清除高亮仍会清空高亮状态。
