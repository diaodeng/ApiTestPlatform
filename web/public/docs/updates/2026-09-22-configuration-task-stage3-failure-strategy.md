# 配置任务阶段化执行阶段三：失败策略、登录失效检测与历史重跑（2026-09-22）

## 新增能力（阶段三）

1. **失败策略**（运行确认弹窗，默认"失败后停止"）：
   - `失败后停止`：任一步骤失败即终止运行，后续阶段不执行（既有行为）；
   - `继续执行后续阶段`：服务端注入 `continueOnFailure`（Agent 既有能力），步骤失败后继续执行后续步骤与阶段，失败阶段照常标记失败；运行终态按是否存在失败判定。
   - 适用场景提示：继续模式下下游阶段依赖上游产出时会级联失败，请自行评估。
2. **登录失效检测提示**：运行/阶段失败收敛时做启发式检测——失败页 URL 或错误信息命中登录特征（login/signin/sso/oauth/登录/未认证/401 等）时，错误信息前缀追加"疑似登录失效，请手动登录或更新凭证后重跑"。检测不改判定结果，仅辅助排障。
3. **历史记录重跑**：运行记录 Tab 中状态为 SUCCESS/FAILED 的运行新增"重跑"按钮（双确认，明确提示会真实执行外站操作）。重跑按原版本号重新创建运行，**凭证/映射/登录态取当前最新配置**——配合阶段二的"强制刷新登录态"，凭证回写后重跑即可通过认证。运行弹窗也可按需改失败策略与步骤参数。

## 设计说明

- 失败策略走 Agent 既有 `continueOnFailure` 运行级通道（`runtime_options.continueOnFailure`），Agent 端零改动；"失败后停止"不注入该键，保持默认终止行为。
- 登录失效检测为服务端纯启发式（模块常量 `_LOGIN_PAGE_URL_FLAGS/_LOGIN_PAGE_MESSAGE_FLAGS`），在阶段 `STEP_FAILED` 与运行 `EXECUTION_FAILED` 两处收敛点接线；未来可升级为按阶段 system_key 精确匹配登录页。
- 重跑是"以最新环境配置重新执行"，不是"重放当时的快照"——这是有意设计：重跑的主要场景就是凭证失效后用新登录态再跑一遍。
- 说明：配置任务的审批/重试在服务端只改数据库状态，Agent 端为单次平铺执行（run_case），无阶段级命令消费端；因此"登录失效→手动登录→重试"闭环中"执行中暂停等人工"暂不具备条件，当前闭环为：失败（带失效提示）→ 用户手动登录/更新凭证映射 → 重跑（最新登录态生效）→ 可选回写凭证供后续使用。

## 变更清单

- `task_run_service.py`：`TaskRunCreateModel.failureStrategy`（stop|continue）写入 run_params 并在 continue 时注入 `runtime_options.continueOnFailure`；模块常量 `_LOGIN_PAGE_URL_FLAGS/_LOGIN_PAGE_MESSAGE_FLAGS` + `_looks_like_login_failure/_annotate_login_failure_hint`；阶段与运行两处 FAILED 收敛点接线检测。
- `RunConfirmDialog.vue`：失败策略单选；`RunRecordTab.vue`：SUCCESS/FAILED 行"重跑"按钮（双确认 + loading），`createRun` 导入。
- 前端构建、后端 ruff、回归 16 用例全部通过；后端已重启。

## 验证

- 浏览器实测：运行弹窗"失败策略"区渲染确认；运行记录按任务 ID 查询后 4 条 FAILED 运行全部显示"重跑"按钮；点击后确认框文案正确（"将使用当前最新的凭证映射与登录态，并真实执行外站操作"），取消后无副作用。
- 失效检测的真实命中场景（登录页失败→提示）建议在下次真实调试运行时观察错误信息前缀。

## 注意事项

- 重跑会真实执行外站操作，已做双重确认；不要在生产任务上随意点击。
- 继续执行模式下，失败阶段的证据完整性校验照常生效（缺失记入 evidence_missing）。
- "执行中人工介入"需 Agent 支持阶段级暂停/恢复命令，属后续演进（需 Agent 端新增命令消费端）。
