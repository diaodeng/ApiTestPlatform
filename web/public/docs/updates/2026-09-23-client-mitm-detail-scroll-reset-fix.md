# mitmproxy 详情区滚动位置重置修复（2026-09-23）

## 变更概述

修复桌面客户端（client_new）mitmproxy 页面的一个使用体验问题：选中一条抓包记录后，在右侧详情区滚动查看响应内容时，只要有**其他**抓包数据进来（`flow_update` 事件），详情区就会被整体重建，滚动条自动回到顶部。数据内容没变，但阅读位置丢失，抓包活跃时几乎无法阅读长响应体。

## 修复内容

- 修改文件：`client_new/ui_web/static/js/pages/mitm.js`。
- **详情刷新条件收紧**：流量更新常驻订阅中，详情区重绘仅在"被更新的正是当前选中的那条流量"时触发（如选中请求刚拿到响应、断点状态变化）；其他流量的更新只刷新列表。
- **滚动位置保持**：详情重绘前记录滚动位置、重绘后还原，并按 `"流量id|标签页"` 判断——只有同一条流量在同一标签页下重绘才恢复位置；切换选中行或切换总览/请求/响应标签页时仍回到顶部显示新内容。
- `dist_dev` 本地打包目录的 `ui_web_static/js/pages/mitm.js` 已同步（本地打包客户端直接从该目录加载前端）。

## 影响

- 后端（mock_handle / mitm_api）无任何改动，事件推送链路不变。
- 选中流量自身的详情更新仍然实时可见，不影响断点放行等操作。
