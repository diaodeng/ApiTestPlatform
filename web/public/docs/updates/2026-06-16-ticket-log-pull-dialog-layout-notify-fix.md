# 日志拉取弹窗布局与通知修复

## 背景

日志拉取弹窗中商家、门店、POSID 三项宽度过短，`modifyTime` 与 `path` 同时展示导致数据类型语义不清；时间切割字段默认常驻，未切割整包下载场景下容易误填。同时，工单详情页手工提交日志拉取时没有把通知配置随请求提交到后端，导致页面配置后实际不会推送通知。

## 变更

1. `LogPullConfigFields` 统一调整布局：
   - 商家、门店、POSID 改为整行铺满。
   - 数据类型为日志时只显示 `modifyTime`；数据类型为数据库时只显示 `path`。
   - 文件上限、压缩包上限移动到时间方式之前。
   - 新增“切割日志”开关，只有开启后才显示时间方式、开始时间、结束时间或时间点范围。
   - 保存方式默认本地。
   - 自动 AI 关闭时隐藏 Agent 与 Provider 选择项，并清空旧值。

2. `LogPullNotifyConfigFields` 调整为按需展示：
   - 默认关闭通知。
   - 只有启用通知后才显示推送项、成功通知、失败通知。
   - 关闭通知时清空推送项，避免隐藏配置继续生效。

3. 前端提交参数收敛：
   - 工单详情页手工日志拉取请求补充 `notifyConfig`。
   - 新增/编辑工单内的日志拉取配置和独立日志拉取页统一清洗隐藏字段。
   - 关闭切割日志时不再提交任何时间范围字段。
   - 日志类型要求 `modifyTime`，数据库类型要求 `path`。

4. 后端通知链路补齐：
   - `TicketLogPullService` 从日志拉取记录 `command_content.notifyConfig` 解析通知配置。
   - 日志拉取成功、外部失败、缺少压缩包地址、内容超限、流程异常时都会按记录通知配置推送。
   - 自动 AI 后续失败通知复用同一解析方法。

## 验证

- 已执行 `uv run python -m py_compile modules\ticket\service\ticket_log_pull_service.py`，后端语法检查通过。
- 前端仍需执行 `cd web && npm run build:prod` 做完整构建验证。
