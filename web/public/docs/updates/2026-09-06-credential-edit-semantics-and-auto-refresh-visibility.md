# 2026-09-06 统一凭证编辑语义修正与自动刷新可见性提升

## 变更主题

修复统一凭证管理两个问题：一是编辑凭证时登录账号"清不掉"（JSON 请求体默认模板被反复自动填回、后端合并式更新导致清空的账号密码在下次编辑时又出现）；二是 UAT 凭证长期未刷新导致过期不易察觉（定时刷新任务正常，但未开启自动刷新的凭证被静默跳过，无任何提示）。

## 对用户的影响

- **默认登录模板只在新增凭证时自动填入**。编辑已有凭证时，登录接口的 JSON 请求体不再被自动改写；用户清空为 `{}` 保存后不会被再次填回。
- 登录接口"接口地址"旁新增**恢复默认模板**按钮，需要账号密码模板时点击一键恢复（`{"username":"${secret.username}","password":"${secret.password}"}`）。
- **清空即删除**：编辑页会把已保存的敏感字段回填到表单；将字段清空后保存，该字段会从凭证中删除（此前是"留空保留原值"，清空的账号密码下次编辑又会出现）。例如凭证不再需要登录账号时，清空用户名/密码保存即可。
- 模板变量校验报错文案细化：引用了 `${secret.username}` 等变量但未填写对应字段时，会提示"请在登录账号区域填写，或点击恢复默认模板后补填账号，不需要账号时请清空模板中的账号密码变量"。
- **凭证列表新增"自动刷新"列**：直接显示每个凭证的自动刷新开启状态（已开启显示间隔；HTTP 登录/刷新模式未开启显示"未开启"黄色标签；不支持的模式显示"不支持"），并新增"最近刷新"时间列。
- **跳过原因可追溯**：定时刷新任务日志现在细分跳过原因（未开启自动刷新 / 未到间隔 / 配置无效 / 租约冲突）。HTTP 登录/刷新模式但未开启自动刷新的凭证，每天最多记录一条操作审计日志提醒，避免凭证静默过期。
- **编辑页新增"到期时间"字段**（刷新与状态折叠区，可留空）：开启自动刷新后，到期前 5 分钟内即使未到间隔也会触发刷新；未开启自动刷新的凭证到期后业务解析会明确报错"凭证已到期"。
- 代码清理：凭证刷新服务中重复定义的内部方法和无调用方的旧响应映射函数已删除，行为无变化。

## 排查结论（为何 UAT 凭证会过期）

定时刷新任务本身运行正常（每 30 分钟执行一次）；UAT 三个凭证（erp-uat-gray02/06/08）此前"自动刷新"开关未开启，定时任务按设计跳过了它们，且跳过原因不可见。2026-09-06 已在页面上为这三个凭证开启自动刷新（间隔 7200 秒）。建议同类 HTTP 登录凭证都开启自动刷新，列表"自动刷新"列可快速确认。

## 注意事项

- "清空即删除"仅对编辑页回填过的主字段生效（Cookie、Header、Token、账号密码、TOTP 密钥、storageState）；附加 Header/Cookie 区域仍按行级增删维护。
- 会使同账号会话互斥的系统开启自动刷新前，请确认账号无他人共用。
