# 2026-06-22 工单日志查看交互与上下文优化

## 结论
- 日志查看弹窗内的搜索结果列表和上下文窗口支持独立放大全屏、还原和最小化。
- 搜索结果数量限制从固定 100 改为页面可配置，默认 500，最大 5000。
- 搜索接口默认不再返回每条命中的上下文，点击命中行时再加载上下文，避免大量结果时响应体过大。
- 上下文上一段、下一段改为使用后端返回的非重叠分页指针，避免重复展示上一段数据。
- 日志编码识别增强，优先兼容 UTF-8、UTF-8 BOM 和 GB18030/GBK 等中文日志编码。

## 变更文件
- `web/src/views/ticket/index.vue`
  - 新增搜索结果和上下文面板的全屏、还原、最小化控制。
  - 新增“结果上限”输入项。
  - 搜索结果默认只展示命中列表，点击命中行后拉取上下文。
  - 上下文翻页只使用服务端 `prevFile/prevLine`、`nextFile/nextLine`，避免前端自行用边界行造成重叠。
- `server/modules/ticket/entity/vo/ticket_log_pull_vo.py`
  - 日志搜索、时间搜索和异常扫描的 `limit` 上限从 500 提升到 5000，默认值改为 500。
- `server/modules/ticket/service/ticket_log_service.py`
  - 上下文翻页指针按当前窗口大小计算下一段中心行，保证相邻段默认不重叠。
  - 增加日志行索引编码版本，已有旧索引会自动重建。
  - 中文关键字搜索走 Python 编码兼容路径，避免 `rg` 对非 UTF-8 日志搜索漏命中或乱码。
  - 文件编码探测优先识别常见中文日志编码，修复上下文中文乱码。

## 验证建议
- 在日志查看弹窗中搜索一个高频关键词，确认结果条数受“结果上限”控制。
- 点击任一搜索结果，确认上下文正常加载且中文不乱码。
- 连续点击“下一段”“上一段”，确认不会重复展示上一段窗口。
- 分别对搜索结果列表和上下文窗口点击“放大全屏”“还原”“最小化”“展开”，确认展示状态正常。

## 风险说明
- 非 ASCII 关键字会使用 Python 搜索以保证编码兼容，极大日志包下会比 `rg` 慢；ASCII 关键字仍优先使用 `rg`。
- 旧 `.lineidx` 行索引会因编码版本变化自动重建，首次查看大日志上下文时可能有一次重建耗时。
