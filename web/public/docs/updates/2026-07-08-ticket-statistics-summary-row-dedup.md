# 2026-07-08 工单统计汇总块重复行修复

## 背景

工单统计页的汇总统计块会直接展示后端返回的 `overview[*Counts]` 数组。部分历史数据存在空字符串、空白、`未填写` 占位值，或 code/name 混用但最终展示为同一个中文标签的情况，导致“解决方式”“关闭结果”“细分问题”等统计块出现多个展示文案相同的行。

典型现象：

1. “解决方式”“关闭结果”中出现两个“未填写”。
2. “细分问题”中出现两个“未填写”。
3. “细分问题”中出现两个“POS客户端支付”。

## 修复内容

后端统计服务先统一 overview 汇总口径：

1. `null`、空字符串、空白字符串和 `未填写` 统一归并为“未填写”。
2. `issueTypeCounts`、`resolutionCounts`、`problemPatternCounts` 等 code/name 维度优先按稳定 code 汇总。
3. `problem_pattern_code` 相同但后续改过 `problem_pattern_name` 时，只保留当前配置中的展示名，历史旧名称数量合并到同一行。
4. `solutionTypeCounts`、`rootCauseTypeCounts` 等单字段维度按归一后的字段值汇总。

前端统计页保留最后一道展示兜底：

1. 每个汇总块表格不再直接使用原始 `overview[block.dataKey]`。
2. 渲染前先调用 `block.format(row)` 得到最终展示文案。
3. 按最终展示文案合并 `count`，空值统一显示为“未填写”。

## 影响范围

影响 `GET /ticket/statistics/overview` 返回的汇总统计数组和工单统计页展示兜底，不改变筛选条件、趋势图和趋势明细的计算口径。

## 验证建议

1. 打开工单统计页，查询包含历史空值或 code/name 混用数据的时间范围。
2. 检查“解决方式”“关闭结果”“细分问题”统计块，同名行应只展示一行且数量为合并后的总数。
