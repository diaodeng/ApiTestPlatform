# 2026-09-14 工单 AI 分析 Agent 断连治理：快速失败 + 心跳判离线 + 客户端看门狗 + 断连自动恢复

## 背景

生产工单 INC00001967826 在"AI 分析中"状态停留近一小时，期间 Agent 日志无任何任务记录。排查确认三层问题叠加：

1. Agent 与服务端的 WebSocket 连接静默死亡（机器睡眠、网络中断等半开连接场景），客户端界面仍显示"运行中"，也不会自动重连；
2. 服务端心跳离线判定存在缺陷：有未完成请求就永久跳过判定，且心跳时间在发送前被无条件刷新，超时判定实际是死代码；
3. AI 分析下发队列对"Agent 已离线"只空转轮询到总超时（默认 1 小时），期间任务一直显示"分析中"。

## 变更内容

### 服务端：AI 下发快速失败

- 提交 AI 分析时检测到 Agent 离线，任务**立即失败**并明确提示"Agent 当前离线，AI 分析任务未下发"，不再排队等待。
- 排队期间 Agent 掉线同样立即失败；连续 3 次转发失败判定连接不可用直接失败。
- 排队等待并发槽位仍属正常限流行为，不受影响。

### 服务端：心跳判定离线（2 分钟）

- 离线判定改为"最后一次收到 Agent 消息（含心跳响应）的时间"，超过 2 分钟无任何消息即判定离线。
- 删除"有未完成请求则跳过离线判定"的逻辑：AI 分析 Worker 在客户端后台线程执行，心跳不会因任务执行而中断，无需跳过。
- 判定离线后同步清理内存连接表、数据库状态置离线，并主动关闭僵尸连接。

### 客户端：心跳看门狗（90 秒）

- Agent 客户端超过 90 秒未收到服务端任何消息（服务端每 30 秒发一次心跳），判定连接已静默死亡，主动断开并自动重连（沿用"断线重连"既有策略）。
- 解决"电脑睡眠唤醒后连接已死但界面仍显示运行中、永不重连"的问题。

### 服务端：执行中连接中断自动恢复

- AI 分析执行中连接断开时，任务进入新状态**"恢复中（等待Agent补交）"**（工单列表显示"AI恢复中"），不判定失败、不发失败通知。
- Agent 端 Worker 继续执行，结果暂存本地，重连后自动补交；服务端恢复扫描任务（每 60 秒）自动写回结果并更新为成功，**不重新调用模型、无需人工重试**。
- 超过恢复期限（任务超时 + 15 分钟）Agent 仍未补交，任务才置为失败并发送失败通知。
- 恢复期间可手动取消（取消后迟到结果不写回）；重试按钮在恢复期间不可用，如需立即重跑请先取消再重新发起。

### 部署

- 新增定时任务"工单AI分析连接中断恢复扫描"（60 秒间隔），部署时执行 `server/sql/20260914_ticket_ai_recovery_scan_task.sql` 自动创建；未执行也可在「任务调度」页面手动创建（任务键 `module_task.scheduler_maintenance.scan_pending_recovery_ai_tasks`）。
- 不执行该 SQL 时，恢复中任务不会被自动写回或置败（但不影响其他功能）。
