# 配置任务版本生命周期管理（2026-09-21）

## 新增能力

针对"发布后不能编辑、无法删除、改一个超时时间要重建整个版本"的问题，补齐版本生命周期操作（发布后不可变的快照原则保持不变）：

- **复制为新草稿**：任意状态版本均可复制。步骤（保留稳定 stepId）、输入绑定、版本变量、起始地址/浏览器/无头/凭证绑定、**阶段切分定义**一并复制，新版本号自动递增，复制件与源版本解耦。改超时时间、基于线上版本微调都走这条路径。
- **撤销发布**：已发布 → 草稿。**仅限从未运行过的版本**（后端校验运行记录数，已有运行记录会被拒绝并提示改用废弃+复制）；撤销后阶段切分保留可继续编辑。
- **废弃**：已发布 → 已废弃（DEPRECATED）。下架后不可再发起运行（运行入口校验拦截），历史运行记录与产物保留可追溯；已废弃版本可复制派生新草稿。
- **删除草稿**：仅草稿可物理删除（阶段定义一并清理），后端校验无运行记录引用。已发布/已废弃版本永久保留。

任务"当前版本"联动：发布将当前版本指针切到该版本；撤销发布或废弃会自动把指针回退到最近一个未废弃的已发布版本，若无则置空。

## 界面变化

版本管理抽屉操作列按状态渲染：草稿=编辑/发布/复制/删除/阶段；已发布=编辑(仅查看)/复制/撤销发布/废弃/阶段；已废弃=编辑(仅查看)/复制/阶段。非草稿版本打开编辑弹窗时顶部显示"仅可查看"提示条且保存按钮禁用。

## 后端接口

- `POST /configuration-tasks/versions/{versionId}/copy`
- `DELETE /configuration-tasks/versions/{versionId}`
- `POST /configuration-tasks/versions/{versionId}/deprecate`
- `POST /configuration-tasks/versions/{versionId}/unpublish`

实现位于 `version_lifecycle_service.py`（ConfigurationTaskVersionLifecycleService），权限沿用 `configuration_task:task:edit`（复制/删除）与 `configuration_task:task:publish`（废弃/撤销发布）。

## 验证

- 配置任务回归测试 20 用例通过；ruff 无新增问题；`npm run build:prod` 通过。
- 浏览器端到端（dev 环境）：复制 v6 → v9 草稿（阶段切分一并复制）；v9 发布 → 撤销发布 → 回草稿；再发布 → 废弃 → 已废弃且任务当前版本指针自动回退到 v8；复制 v6 → v10 草稿 → 删除成功；已发布版本编辑弹窗显示只读提示条且保存按钮禁用。

## 注意事项

- 运行消息下发时步骤实时读取版本 steps_json，因此已发布版本绝不允许内容变更或物理删除——这是快照不可变原则的技术依据，不要为了图方便绕过。
- 撤销发布仅对无运行记录版本开放是有意设计；有运行记录时请使用"废弃 + 复制"。
