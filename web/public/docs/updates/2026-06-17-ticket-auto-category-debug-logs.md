# 工单自动归类排障日志增强

## 背景

工单同步配置页的“统计未归类工单”调用 `GET /ticket/sync/auto-category/stats`，该接口只统计总数、已归类数、未归类数和占比，不会触发自动归类。真正执行自动归类的是 `POST /ticket/sync/auto-category/reclassify`。

## 调整内容

1. `GET /ticket/sync/auto-category/stats` 增加入口和统计完成日志，明确记录“仅统计，不执行自动归类”。
2. `POST /ticket/sync/auto-category/reclassify` 增加入口参数日志，记录策略、分页、是否仅未归类、是否全量、是否强制覆盖、提示词编码和正则规则数量。
3. 批量重归类过程增加逐条日志，记录当前处理工单、标题/描述长度、执行策略、跳过原因、成功回填字段和失败异常。
4. AI 分类统计链路增加场景开关、防重、上下文、Provider/Prompt、模型执行和回填结果日志，便于判断是配置未开、已有成功结果、AI 未返回，还是回填阶段异常。
5. 同步配置页按钮文案由“一键统计未归类工单”调整为“统计未归类工单”，统计成功提示明确不会触发自动归类。

## 排查方式

1. 只看未归类数量：点击“统计未归类工单”，服务日志会出现 `工单未归类统计开始` 和 `工单未归类统计完成`。
2. 执行归类：点击“按当前配置重归类”或“强制重归类全部”，服务日志会从 `工单批量重归类开始` 开始记录每条工单的处理过程。
3. 如果未执行，优先查看日志中的 `跳过` 原因，例如当前场景未开启 AI 分类统计、已有相同文本的成功 AI 分类结果、Provider/Prompt 未配置、正则规则为空等。

## 风险说明

日志不会输出完整工单描述正文，只输出工单号、ID、标题长度、描述长度、评论数量、配置编码和执行结果，降低排障日志泄露业务正文的风险。
