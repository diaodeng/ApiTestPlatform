# 日志内存分析全面升级：搜索管道引擎、图表日志双向联动、资源曲线独立入口

- 变更时间：2026-09-01
- 影响模块：工单日志查看器 - 内存分析、日志拉取记录管理页

## 变更内容

1. **扫描引擎升级**：内存分析扫描层从自研逐行扫描切换为复用日志搜索管道（`LogService.search`，rg 流式优先，缺失 rg 自动降级 Python，保留既有内存/并发/字节数保护）。进度按文件粒度推送，不再提供单文件内行级百分比。
2. **数据点携带行号与 epoch**：每个数据点新增 `line`（命中行号）与 `epoch`（本地时间 epoch 秒）；结果新增 `totalHits / parsedCount / skippedLineCount` 统计，命中但解析失败的行跳过并计数，不中断分析；解析成功点数达 20000 硬上限即停止扫描并标记截断。
3. **布局修复**：日志查看弹窗内容区支持纵向滚动、搜索工具栏吸顶；内存分析面板支持"最小化/展开"；点击日志行时内存面板自动最小化，解决曲线展开后日志详情被顶出可视区看不到的问题。
4. **图表 ↔ 日志双向联动**：
   - 点曲线数据点 → 直接打开该点对应日志行的上下文（点自带精确文件+行号），内存面板自动最小化；
   - 点搜索结果日志行 → 曲线上按时间就近画红色虚线标记（标注行号）；
   - 内存分析跟随当前搜索的文件范围过滤。
5. **资源曲线独立入口（日志拉取记录管理页）**：操作列新增"曲线"按钮，打开独立弹窗：上半部分为该记录全局资源曲线，下半部分为数据点列表（分页，含时间/文件/行号/CPU/内存/线程）；点击曲线点或列表行打开完整日志查看器并跳转对应行上下文。

## 同日追加：分栏联动布局重构

- 原方案"点曲线点自动最小化图表"交互不佳（联动后看不到曲线，需手动再展开）。已重构为**图表-日志分栏布局**：宽屏左右分栏（图表默认 40%，可拖拽分隔条调整，会话内记忆），窄屏（<1280px）自动上下分栏；点曲线点/点日志行时双方保持同屏联动，不再自动折叠；面板 header 提供"收起图表"回到单栏，工具栏"内存分析"按钮随时重新展开。结果表格宽度按右栏实际宽度自适应（ResizeObserver）。

## 说明

- 日志时间不带时区，曲线横轴按服务器本地时间展示。
- 曲线渲染使用 ECharts lttb 采样，数据点在返回前已降采样到 2000 点，2 万原始点约 2~3MB JSON。

## 同日追加：交互修复与体验优化

1. **点击时间轴也能跳日志**：此前只有点到曲线上极小的数据点符号才会触发日志跳转（曲线默认不渲染符号，实际几乎点不到）。已改为 ECharts 画布级点击（`zr` 事件 + 像素坐标换算时间 + 二分就近匹配数据点）——点击曲线、时间轴、图表空白处均可跳转到最近数据点对应的日志行；点击图例、缩放条等控件不会误触发。
2. **横轴改为真实时间轴**：从 category（把点均匀铺开）改为 time 轴（按数据点真实时间戳定位），修复降采样后采样间隔不均导致的时间视觉失真，跨天数据正常显示日期；反向联动标记线同步改为按毫秒时间定位。
3. **修复点击搜索结果时页面闪烁**：上下文加载不再复用全局 loading 遮罩（旧遮罩覆盖整个内容区，加载时面板高度类来回切换导致闪跳），改为在日志明细块内部就地显示加载提示；高亮刷新监听从深度监听改为引用监听，减少一次全量重算。
4. **上下文自动滚动定位**：点击曲线点或搜索结果行后，日志明细区自动滚动到目标行（找不到精确行时就近定位），不再需要手动翻找。
5. **解析兼容性**：监控行时间戳毫秒分隔符兼容逗号（`2026-08-30 15:15:24,372`）和点号（`2026-08-30 15:15:24.372`）两种格式，此前点号格式的行会被静默跳过。
6. **降低数据库压力**：批量扫描多个文件时，仅首个文件读取搜索保护配置，后续文件使用同等默认阈值，避免逐文件重复查库（实测每次查库约 100ms，200 文件累计可省 20s+）。
