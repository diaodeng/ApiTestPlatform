# 配置任务版本步骤详情弹窗修复与证据预校验（2026-09-21）

## 修复内容

- 修复版本编辑弹窗中"新增步骤"或点击"详情"无响应的问题：浏览器控制台报 `Uncaught (in promise) TypeError: Cannot read properties of null (reading 'elementText')`。
- 根因：新增步骤时手工构造的步骤对象 `targetSnapshot` 固定为 `null`，而默认动作 `fill` 属于需要定位的动作；步骤详情弹窗的"定位与快照"卡片直接绑定 `targetSnapshot.elementText` 等内部字段，`null` 上取值导致渲染中断，弹窗表现为"点详情无响应"。历史草稿数据中需要定位但缺少 `targetSnapshot` 的步骤点详情同样会触发。
- 修复方式（前端三处）：
  - `VersionStepTable.vue` 新增步骤改用 Web 用例编辑器同款的 `createDefaultStep` 工厂构造，需要定位的动作自动携带默认定位快照；
  - `openDetail` 打开弹窗前为"需要定位但缺 targetSnapshot"的步骤补默认快照，兜底历史数据；
  - `StepDetail.vue` 定位与快照卡片增加 `targetSnapshot` 存在性守卫，极端情况下显示"当前步骤缺少定位快照数据"空态而不是白屏报错。

## 新增能力

- 阶段切分弹窗保存时按后端发布校验同口径预校验证据模式：
  - "必需"模式但阶段内没有截图步骤 → 提示需添加"截图 / 采集证据"步骤；
  - "前后对照"模式缺少修改前或修改后截图步骤 → 明确提示缺哪类；
  - "不要求"模式却声明了必需类型 → 提示清空或调整模式；
  - 声明的"必需类型"在阶段内截图步骤中不存在 → 提示缺少的类型。
  预校验把原本拖到发布才暴露的问题提前到保存阶段时提示，错误文案与后端一致。

## 语义澄清

阶段配置里的"证据模式"只是约束声明，不会在阶段执行完后自动截图；业务证据截图必须在版本步骤中显式添加"截图 / 采集证据"（`capture_screenshot`）步骤。用户说明已补充"证据模式与截图步骤的关系"章节说明两者分工与各模式校验规则。

## 验证

- `npm run build:prod` 构建通过。
- 修复路径：新增步骤自动打开详情弹窗可正常渲染；对需要定位的历史步骤点详情不再报 `elementText` 空指针。

## 使用提示

发布报"阶段 xxx 要求证据，但未配置 capture_screenshot 步骤"时的处理路径：编辑版本 → 在该阶段的步骤区间内新增"截图 / 采集证据"步骤（详情中设置证据类型）→ 保存版本 → 阶段切分保存时若配置不匹配会直接提示，无需等到发布。
