# 工单日志详情选区高亮回归修复

## 背景

工单详情页日志搜索结果详情中，之前支持在日志上下文区域选中文本后，自动把选中文本作为临时高亮词，并写入高亮候选词输入框。日志详情 tab 拆分后，实际渲染路径退回到 `<mark>` 分片方式：选中文本后高亮词变更会触发日志内容 DOM 重建，浏览器原生选区被打断，表现为选中文本不能稳定高亮，也不能稳定保留为可 `Ctrl+C` 复制的选区。

## 本次修复

1. `TicketDetailLogPullTab.vue` 恢复 CSS Highlight API 主路径：支持的浏览器使用 `CSS.highlights` + `Range` 对 `.log-context-line-content` 文本节点注册非侵入高亮，不改写日志内容 DOM。
2. 不支持 CSS Highlight API 的浏览器继续使用 `<mark>` 分片兜底，避免功能缺失。
3. 高亮词、日志上下文翻页、上下文面板最小化/还原变化后，通过 `nextTick` 重新注册原生高亮；tab 关闭和组件销毁时清理已注册的高亮。
4. 高亮输入框改为固定单行高度并保留滚动，多个高亮词不会把详情标题工具栏撑高，减少页面抖动。

## 行为说明

- 在日志详情正文中选中文本后，选中文本会进入高亮候选词输入框，并立即高亮当前上下文中相同文本。
- 浏览器选区仍保留在日志正文中，可直接使用 `Ctrl+C` 复制。
- 取消选区或选区移出日志详情正文后，只移除本次选区临时追加的高亮词；用户手工输入或其他正常高亮词保留。
- 双击选中仍走浏览器原生选区流程，选中词会自动作为临时高亮词。

## 编辑器替代 pre 的分析

短期不建议只为日志搜索详情把 `<pre>` 换成编辑器组件。

- 性能：编辑器的优势主要在超长文本虚拟滚动、语法高亮、搜索、折叠等能力。当前日志详情只展示后端返回的上下文窗口，不是整份日志全文，渲染量通常可控；引入编辑器会增加初始化成本、依赖体积和生命周期处理复杂度。
- 选区与高亮：当前问题的根因不是 `<pre>` 本身，而是选区后重建日志 DOM。恢复 CSS Highlight API 后，`<pre>` 可以保留原生复制、行号展示和低成本渲染。
- 原始行号：使用 Monaco/CodeMirror 也可以保留原始行号，但不能直接依赖编辑器默认行号，因为默认行号会从 1 开始。需要自定义 gutter/line number formatter，把后端返回的 `start` 或每行 `line` 映射到真实日志行号。
- 后续场景：如果未来要在详情中展示整份大日志、支持虚拟滚动、多文件标签、内置搜索和跳转，再引入 CodeMirror 6 或 Monaco 更合适；届时应把日志查看器独立成组件，并明确原始行号映射、复制内容和高亮来源。

## 验证建议

1. 在 Chrome/Edge 中打开工单详情日志查看器，搜索命中后选中日志详情中的文本，确认选区仍可复制且相同文本立即高亮。
2. 点击日志详情外部取消选区，确认本次选区高亮消失，其他手工高亮词保留。
3. 输入多个高亮词，确认高亮输入框不会撑高工具栏。
4. 使用上一段/下一段翻页，确认已有高亮词在新上下文中继续生效。
