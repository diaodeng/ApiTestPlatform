# 工单链路内存泄漏治理

- 修复 Agent WebSocket 分片注册表（事件分片组、响应分片）在分片丢失、断流或连接异常后条目永久驻留的内存泄漏；超时未凑齐的分片组由心跳任务定期清理，单个事件分组超过 2048 片时整组丢弃，孤儿响应分片直接丢弃不再重建条目。
- 日志拉取记录查询新增轻量版本，状态轮询、重拉、停止、删除、下载等后台与控制路径不再把兆级压缩日志正文读进内存；只有查看日志正文的两条路径保留全量读取。
- 工单 AI 分析摘要序列化不再回读提示词、原始输出和任务上下文三个大字段；恢复执行的任务列表同样按延迟列加载。
- 工单 AI 执行审计对响应文本、请求/响应载荷做集中超长裁剪：80 万字节日志正文等大文本不再整包写入内存和审计长文本列，完整内容以工作区文件留档为准；审计详情页仍可看到定位所需的头部信息。
- 部署层为 API、Celery Beat、Celery Worker 三个进程注入 `MALLOC_ARENA_MAX=2` 并写入 Dockerfile 环境变量，缓解多线程大块分配导致的堆碎片 RSS 只增不减问题。
- 本轮为服务端内存治理，不改变任何接口路径、参数和响应结构，前端无需调整。
