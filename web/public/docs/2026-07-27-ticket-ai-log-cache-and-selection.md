# 工单 AI 分析日志缓存与选择

## 背景

工单 AI 分析在日志正文未入库、需要整包日志分析时，Agent 原先会把压缩包下载到每个任务自己的 `source_logs.zip`，因此同一工单反复分析会重复下载、重复解压相同日志。

## 调整内容

1. Agent 按 `工单ID + 日志拉取记录ID + 日志来源指纹` 在 AI 工作区根目录下保存固定缓存：
   `log_cache/ticket_<ticketId>/log_pull_<recordId>/<sourceHash>/`。
2. 缓存保存原始压缩包、解压后的 `source_logs/` 及 `cache_manifest.json`。只有来源标识、压缩包和解压目录同时有效时才会命中缓存，避免使用未完成下载的文件。
3. 首次执行继续下载/解压；后续分析复用缓存目录，并在 Agent 阶段日志记录“复用本地整包日志缓存”。如果 Agent 机器可以直接访问 `storagePath` 本地归档，则不下载，直接基于该归档建立解压缓存。
4. 任务提示词会指向实际缓存日志目录，`logs_ai_digest.txt`、任务级 `source_logs_manifest.json` 和时间窗口截取结果仍保留在本次任务工作区，保证任务可追溯。
5. 手动发起 AI 分析时，弹窗展示当前工单所有“下载成功”的日志拉取记录；默认选择最新成功记录，也可手工改选指定记录。未选择时后端同样回退到最新成功记录。
6. 后端拒绝不存在、非当前工单或未成功的日志记录，避免跨工单引用或分析未完成日志。

## 影响与运维

- 缓存仅位于执行该 Agent 的本机；切换到另一台 Agent 时，该 Agent 会首次下载一次。
- 当日志来源 URL 或本地归档文件的大小、修改时间变化时会生成新的缓存目录，不覆盖旧缓存，确保重新下载后的内容不会误用旧数据。
- 缓存不随单个 AI 任务删除。需要回收磁盘时，应在 Agent 停止执行时按 `log_cache` 下的工单目录制定保留期清理策略，避免删除正在分析的目录。

## 验证

- 服务端提示词单测覆盖缓存目录替换。
- Python 编译检查覆盖 Agent 缓存逻辑和服务端日志选择逻辑。
- 前端生产构建覆盖手动日志选择控件。
