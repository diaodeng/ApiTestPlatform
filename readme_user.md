## 平台简介

API Test Platform（QTestRunner）是一个功能强大的 API 测试平台，支持：

- **Web 端**：通过浏览器管理 API 接口、编写测试用例、执行测试、查看报告
- **桌面客户端**：本地抓包（mitmproxy）、代理设置、辅助调试
- **定时任务**：自动执行测试套件
- **团队协作**：多环境管理、转发规则、Mock 服务

## 功能介绍

### 1. 接口管理
管理和调试 API 接口，支持：
- 按文件夹归类接口
- 拖拽移动接口位置
- 快速调试
- 一键另存为测试用例

### 2. 用例管理
编写和管理 API 测试用例，支持：
- 多步骤测试流程
- 参数化变量
- 数据断言
- 自定义脚本（Python）
- 批量执行

### 3. 环境管理
管理不同测试环境：
- 测试环境、预发环境、生产环境
- 全局变量定义
- 环境隔离

### 4. 配置管理
公共配置复用：
- 公共请求头
- 公共变量
- 默认超时设置

### 5. 测试套件
将多个用例组合成套件：
- 按顺序执行
- 支持并发
- 批量执行计划

### 6. 定时任务
自动化测试：
- 定时执行
- 循环执行
- 执行结果推送（飞书机器人）

### 7. 报告管理
查看测试结果：
- 执行日志
- 响应数据
- 断言结果
- 失败原因分析

### 8. 客户端管理
分布式执行：
- Agent 客户端注册
- 远程执行用例
- 流量转发

## 快速开始


## 详细使用指南

### 创建第一个测试用例

#### 步骤 1：创建环境

1. 进入 **测试管理 → 环境管理**
2. 点击 **添加环境**
3. 填写环境信息：
   - 环境名称：如「测试环境」
   - 环境地址：如 `http://api.test.com`
4. 添加全局变量（可选）：
   - 变量名：`base_url`
   - 变量值：`http://api.test.com`
5. 点击 **保存**

#### 步骤 2：创建项目

1. 进入 **测试管理 → 项目管理**
2. 点击 **添加项目**
3. 填写项目信息：
   - 项目名称：如「用户中心」
   - 项目描述：项目说明
4. 点击 **保存**

#### 步骤 3：创建模块

1. 进入 **测试管理 → 模块管理**
2. 点击 **添加模块**
3. 选择所属项目
4. 填写模块信息：
   - 模块名称：如「用户登录」
5. 点击 **保存**

#### 步骤 4：创建用例

1. 进入 **测试管理 → 用例管理**
2. 点击 **添加用例**
3. 选择所属项目、模块、环境
4. 填写用例信息：
   - 用例名称：如「登录成功」
   - 请求方式：`POST`
   - 请求路径：`/api/user/login`
5. 在 **请求参数** 中填写：
   ```json
   {
     "username": "test",
     "password": "123456"
   }
   ```
6. 在 **断言** 中添加预期结果：
   - 断言类型：包含
   - 预期值：`"code":0`
7. 点击 **保存**

#### 步骤 5：执行用例

1. 在用例列表中，找到刚创建的用例
2. 点击 **执行** 按钮
3. 选择执行环境
4. 点击 **确定**

#### 步骤 6：查看报告

1. 进入 **测试管理 → 报告管理**
2. 找到刚执行的报告
3. 点击查看详情：
   - 请求信息
   - 响应内容
   - 执行日志
   - 断言结果

### 使用进阶功能

#### 使用变量

在请求中使用变量：

```
# 定义变量（环境管理或用例中）
username = "test"

# 使用变量
${username}        # 替换为 test
${base_url}/login   # 拼接完整地址
```

#### 使用断言

支持的断言类型：

| 类型 | 说明 | 示例 |
|------|------|------|
| 包含 | 响应包含某字符串 | 断言值：`"success"` |
| 等于 | 完全相等 | 断言值：`{"code":0}` |
| 大于/小于 | 数值比较 | 断言值：`100` |
| 正则匹配 | 正则表达式 | 断言值：`\d+` |
| JSON路径 | 提取并验证 | 断言值：`$.data.token` |

#### 使用数据提取

从响应中提取数据供后续步骤使用：

```json
{
  "extracts": [
    {
      "name": "token",
      "json_path": "$.data.token",
      "regex": null
    }
  ]
}
```

后续步骤中使用：`${token}`

#### 使用自定义脚本（debugtalk）

在项目维度的 debugtalk 中编写辅助函数：

```python
from helper import some_helper

def get_sign(params, secret):
    """生成签名"""
    import hashlib
    sorted_params = sorted(params.items())
    sign_str = '&'.join([f"{k}={v}" for k, v in sorted_params])
    return hashlib.md5(sign_str.encode()).hexdigest()

def before_request(config):
    """请求前钩子"""
    config["headers"]["Authorization"] = "Bearer ${token}"
    return config
```

#### 配置转发规则

将请求转发到不同地址：

1. 进入 **测试管理 → 转发规则**
2. 添加规则：
   - 规则名称：`测试环境转发`
   - 匹配路径：`/api/prod/*`
   - 转发地址：`http://test-api.com`
3. 在用例执行时选择转发规则

#### 使用 Mock 服务

1. 进入 **测试管理 → Mock管理**
2. 添加 Mock 规则：
   - 接口路径：`/mock/user/info`
   - 请求方法：`GET`
   - 响应数据：`{"name": "测试用户", "age": 25}`
3. 启用 Mock 后，对应请求将返回模拟数据

#### 创建测试套件

1. 进入 **测试管理 → 测试套件**
2. 点击 **添加套件**
3. 填写套件信息：
   - 套件名称：「登录流程测试」
4. 从用例列表中选择要执行的用例
5. 设置执行顺序
6. 保存并执行

#### 设置定时任务

1. 进入 **系统管理 → 定时任务**
2. 点击 **添加任务**
3. 配置任务信息：
   - 任务名称：`每日回归测试`
   - 执行表达式：`0 0 2 * * ?`（每天凌晨2点）
   - 执行方式：执行测试套件
   - 选择套件：登录流程测试
4. 可选：配置飞书推送
   - 开启机器人推送
   - 填写机器人地址和密钥
5. 保存即可自动执行

## 常见问题

### Q1: 用例执行失败怎么办？

1. 进入 **报告管理** 查看详细日志
2. 检查：
   - 环境变量是否正确
   - 请求地址是否可访问
   - 参数格式是否正确
   - 断言条件是否合理

### Q2: 如何处理登录态？

在 debugtalk 中编写登录脚本：

```python
def login_and_get_token():
    """登录获取token"""
    import requests
    resp = requests.post("${base_url}/api/login", json={
        "username": "admin",
        "password": "admin123"
    })
    return resp.json()["data"]["token"]
```

然后在后续请求中使用 `${token}`

### Q3: 如何实现接口依赖？

使用数据提取和引用：

1. 步骤1：提取依赖数据
   ```json
   {
     "name": "order_id",
     "json_path": "$.data.orderId"
   }
   ```

2. 步骤2：在后续请求中引用
   ```
   /api/order/${order_id}
   ```

### Q4: 如何实现并发执行？

1. 创建测试套件
2. 选择要并发的用例
3. 设置并发数 > 1
4. 执行套件

### Q5: 如何推送执行结果？

1. 在定时任务或执行时开启推送
2. 配置飞书机器人：
   - 机器人地址（Webhook URL）
   - 关键字
   - secret（加签密钥）
   - 需要@的用户

### Q6: 数据提取工具

- **jmespath**：[官网](https://jmespath.org/) - JSON 数据提取
- **jsonpath**：[在线工具](https://www.jsonpath.cn/) - JSONPath 验证

### Q7: 变量使用注意

```bash
# 正确用法
${variable}
${base_url}/api/login

# 错误用法
$variable              # 缺少大括号
${var}extra           # 变量后直接跟字符
```
