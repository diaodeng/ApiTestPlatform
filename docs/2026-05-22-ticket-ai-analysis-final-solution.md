# 工单AI分析最终方案落地记录

## 已实现

- 工单详情页新增 `AI分析` 标签页，可查看最新分析结果和任务历史。
- 新增项目版本仓库映射管理，并拆分出独立菜单页面，支持按 `项目 + 版本标识` 维护 `仓库地址 / 分支 / 本地仓库路径 / 工作区根目录 / Worker命令`。
- 新增 AI 分析任务表，记录任务上下文、执行命令、原始输出、结构化结果和状态。
- AI 分析任务后台通过 `codex exec` 执行，默认读取工单、时间线和最新日志内容，并把结构化结果回写到 `ticket.ai_analysis`、`ticket_rca` 和 `ticket_event`。
- AI 分析提交前需要工单具备版本号，系统按“工单所属项目 + 版本号”自动匹配仓库映射。
- 服务启动时会初始化 AI 相关系统参数，并恢复待执行的 AI 任务。

## 未实现

- 自动修复代码并提交。
- 自动部署验证和回滚。
- 多 Worker 节点调度与负载均衡。
- 代码仓库克隆、缓存清理和分支同步的独立管理页面。

## 配置键

- `ticket.ai.worker.command`
- `ticket.ai.worker.model`
- `ticket.ai.worker.sandbox`
- `ticket.ai.worker.timeoutSec`
- `ticket.ai.workspace.root`

## 备注

- 当前实现优先保证“可继续做”的数据结构和执行链路，后续可以在此基础上补充 Worker 独立服务、仓库缓存和自动修复闭环。
