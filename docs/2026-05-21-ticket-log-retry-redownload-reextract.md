# 工单日志记录级动作改造

## 背景
日志拉取列表和详情页需要提供记录级操作入口，方便在失败、归档文件缺失或时间范围截取错误时直接处理已有记录。

## 变更范围
- 日志拉取列表新增 `重新拉取`、`重新下载`、`重新截取` 操作。
- 日志查看详情页增加同类动作入口，便于在弹窗中直接处理当前记录。
- 后端新增三类接口：
  - `POST /ticket/log-pulls/{record_id}/retry`
  - `POST /ticket/log-pulls/{record_id}/redownload`
  - `POST /ticket/log-pulls/{record_id}/reextract`

## 行为说明
- `重新拉取`：基于原记录恢复提交参数，重新创建一条日志拉取任务。
- `重新下载`：从原始压缩包地址再次下载归档文件，并恢复到原存储位置。
- `重新截取`：按当前查看时间范围重新切片日志，并更新当前记录的入库内容。

## 兼容性
- 重新拉取优先恢复原始时间模式参数；历史记录若缺少点位参数，则回退到已保存的开始/结束时间。
- 记录级动作不会修改工单主表，只更新日志拉取记录和时间线事件。
