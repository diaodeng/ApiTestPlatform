# 2026-05-20 工单日志拉取变更记录

## 变更目标
- 为工单系统增加自动日志拉取、状态跟踪、异常记录、归档和日志查看能力。

## 变更内容
- 后端新增日志拉取记录模型、VO、DAO、服务。
- 后端新增日志拉取配置接口、提交接口、记录列表接口、日志内容接口。
- 工单列表和工单详情返回补充最新日志拉取摘要。
- 服务启动时自动恢复未完成的日志拉取任务。
- 日志拉取外部地址、Cookie、归档和轮询配置统一迁移到系统参数：
  - `ticket.logPull.external`
  - `ticket.logPull.storage`
- 前端工单列表新增日志拉取状态列。
- 前端工单详情新增日志拉取标签页，支持：
  - 提交日志拉取任务
  - 跳转到参数配置管理维护外部地址、Cookie 与本地/FTP 存储
  - 查看拉取记录状态与异常
  - 查看压缩入库的日志文本

## 验证记录
- `uv run python -m compileall ...ticket... server/server.py`：通过
- `uv run ruff check ...ticket... server/server.py`：通过
- `cd web && npm run build:prod`：通过

## 风险与后续
- FTP 配置当前保存在系统参数表中，属于敏感信息，生产环境建议配合数据库权限和运维审计使用。
- 线程池任务在单进程内执行；若后续扩展多实例或多 worker，建议改为 Celery/统一任务队列。
- 外部平台接口依赖真实网络与第三方可用性，本地仅完成编译和构建验证，未在当前环境联调真实接口。
